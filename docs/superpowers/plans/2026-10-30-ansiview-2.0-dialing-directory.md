# AnsiView 2.0: Dialing Directory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) with superpowers:test-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap item 63 (owner request): turn plan 7's BBS address book into a dialing directory in the spirit of the classic DOS terminal phonebooks: a table of BBSes with call history, notes and tags, per BBS credentials (passwords in the Keychain only), automatic login scripts, a dialing panel with redial, keyboard macros, and import and export.

**Owner's words:** "The terminal, lets make it where we can save and 'dial up' BBS's. So we can have a list of BBS's we go to, it saves different login/passwords for each BBS, etc.. I really liked Terminate back in the day how it managed everything." The design is original: no name, text, layout or artwork from Terminate or any other program.

**Architecture:** Pure logic in AnsiCore with byte level tests: `BBSAddressBook.swift` (the `BBSEntry` gains the new per entry settings, old JSON still decodes), `DialingDirectory.swift` (the directory container, migration from the plan 7 key, search, tags, sorting, reordering, call history, export and import), `LoginScript.swift` (expect/send steps, an ANSI stripping prompt matcher, the script runner with timeouts), `Macros.swift` (macro escape parsing, global and per entry slots), `RedialQueue.swift` (the dialing state machine), `SyncTermImport.swift` (syncterm.lst reader), `PasswordStore.swift` (the credential key, a protocol, an in memory store and the Keychain store) and `DialPanelScreen.swift` (the dialing panel's text screen, drawn with the bitmap font renderer). The app adds `App/DialingDirectory.swift` (store, window, table), `App/DialingEntryEditor.swift` (SwiftUI editor sheet, global macros, help popovers) and `App/DialingPanel.swift` (the dialer that drives terminal windows through the queue, and its panel); `App/BBSTerminal.swift` gains login, macros, password, capture on connect and hooks for the dialer; `App/BBSConnect.swift` is removed (the directory replaces it). Nothing goes into `Shared/` and no extension gains anything.

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, Security framework (Keychain), AppKit (`NSTableView` for the directory: column sorting, drag reorder and tooltips), SwiftUI (editor sheets), XcodeGen.

## Rulings

1. **Keep `BBSEntry`, add fields.** The plan 7 type keeps its name and fields (the terminal uses it). New fields, each defaulted when missing so plan 7 JSON decodes: `notes` "", `tags` [], `lastCalled` nil, `totalCalls` 0, `captureOnConnect` false, `captureFolderBookmark` nil (security scoped bookmark data) and `captureFolderName` nil (shown in the editor), `modemSound` (`.playbackSetting` default, `.on`, `.off`), `macros` (10 strings for Option-1 ... Option-0, empty means unset), `autoLogin` true, `loginScript` (the default script, ruling 4), `busyText` (default `all nodes are busy|nodes are busy|no free nodes|system is busy`). Cost if wrong: a field renamed later needs a decoder alias.
2. **Storage and migration.** The directory is JSON under the app's standard defaults key `dialingDirectory`: `{"version":1,"entries":[...],"globalMacros":[...],"showAtLaunch":false,"redialAttempts":3,"redialDelay":10}`, dates ISO 8601 (whole seconds). On load, when `dialingDirectory` is missing, the plan 7 array under `bbsAddressBook` is decoded into the entries and the old key is left in place (a downgrade still finds its book); the first save writes the new key. Both keys missing gives the example entry; a present but unreadable new key gives an empty directory (never the example over the user's data). Cost if wrong: a downgrade sees the old book without later edits.
3. **Credentials.** Usernames are in the entry; passwords only in the Keychain as `kSecClassInternetPassword` items with `kSecAttrServer` = host (lowercased), `kSecAttrPort`, `kSecAttrAccount` = username, `kSecAttrProtocol` = telnet, label `AnsiView BBS: <name>`. Using the legacy (file based) login keychain, which sandboxed apps may use with no extra entitlement (verified in Task 9 with a sandbox signed harness). A password needs a username (the key needs an account; the editor disables the field until a username is typed). Editing host, port or username moves the item; deleting an entry deletes its item unless another entry has the same host, port and username (they share one account). Export never includes passwords (the model holds none). Cost if wrong: two entries for one account share a password, which is what the Keychain models anyway.
4. **Login scripts.** A script is a list of steps `{expect, send, text, timeout}`; `send` is `username` (the username then CR), `password` (the password then CR), `text` (the step's text with macro escapes, ruling 6) or `returnKey` (CR). `expect` is matched case insensitively, ignoring ANSI escape sequences (CSI, ESC with intermediates, OSC/DCS/APC/PM/SOS strings), control bytes and spaces, so `login:` matches `L` `ESC[1;33m` `ogin :`. `|` separates alternatives (`login:|name:`). An empty `expect` sends at once. Each step waits at most its timeout (default 30 s), then the script stops and the status line says which prompt never came. Text after a match carries over to the next step. Default script (inferred from the prompts these packages print by default; not checked against live systems, agents may not log in): step 1 expects `login:|name:|nn:|handle:|user id:` and sends the username; step 2 expects `password:|pw:` and sends the password (Synchronet `Login:`/`Password:`, Mystic `Login:`/`Password:`, WWIV `NN:`/`PW:`, ENiGMA 1/2 `Username:`/`Password:`). The script runs on connect when `autoLogin` is on and a username is set; Terminal > Log In runs it again. A step whose value is missing (no username or password) stops the script with a message instead of sending an empty line. Cost if wrong: the user edits the steps for one BBS.
5. **Busy.** `busyText` alternatives are matched the same way during the first 30 s after connect; a match hangs up and counts as busy (ruling 7). An empty busy text never matches.
6. **Macros.** Ten slots, Option-1 ... Option-9, Option-0. An entry's non empty slot wins over the global slot. Text escapes: `\r` CR, `\n` LF, `\t` TAB, `\e` ESC, `\\` backslash, `\xHH` a byte; an unknown or incomplete escape is sent as typed. Other characters use the entry's encoding (CP437 or UTF-8). Option-digit no longer types `¡™£¢∞§¶•ªº` in the terminal (none is common on a BBS). Cost if wrong: one of those characters needs a paste.
7. **Dialing and redial.** Dial takes the selected entries in table order. Each attempt opens a hidden terminal window for the entry and connects; states shown: resolving and connecting (Network.framework does both inside one connect, so the panel shows `Connecting` with the address), connected, refused, busy, not found, timed out, failed. On connect the entry's `lastCalled` and `totalCalls` update, the window comes forward and the dial queue ends (a later busy match inside the busy window reopens the panel and continues the queue). On failure the panel waits `redialDelay` seconds (default 10, 0 to 600) and dials the next entry, wrapping; a pass is one trip through the queue; after `redialAttempts` passes (default 3, 1 to 99) the panel says nobody answered. Stop ends everything and closes the attempt's window; Dial Now skips the wait. Cost if wrong: the order of retries.
8. **Dialing panel look.** An original design: a 52 x 13 text screen drawn by `AnsiRenderer` with the IBM VGA font, a double line box in bright cyan on blue with a bright white title `AnsiView Dialer`, rows for BBS name, address, attempt (`2 of 3`, pass and queue position), status, elapsed or countdown seconds, and a bar of `█`/`░` blocks for the wait; AppKit buttons under it (Stop, Dial Now, Skip). The dial sound is the existing synthesized handshake (it already dials touch tone digits), played per the entry's `modemSound` (Playback > Modem Sounds when set to follow it).
9. **Capture on connect.** When on, the session is captured to `<folder>/<name> yyyy-MM-dd HHmmss.ans` from the moment of connect; the folder is a security scoped bookmark chosen in the editor. This needs `com.apple.security.files.bookmarks.app-scope` (Apple's documented requirement for app scoped bookmarks, so the folder can be reopened in a later launch); it is the only new entitlement. If the bookmark is stale or the folder cannot be written, the status line says so and the session continues uncaptured.
10. **Opening choice.** The directory window has `Show at launch`; when on, the app shows the directory after launching (`applicationDidFinishLaunching`).
11. **Export and import.** File format `{"format":"AnsiView Dialing Directory","version":1,"entries":[...]}` (pretty printed, sorted keys, no passwords, capture bookmarks removed since they only work on this Mac). Import reads that format, a plan 7 address book array, or a stored directory; imported entries get fresh ids, and an entry with the same name, host, port and username as an existing one is skipped. SyncTERM `syncterm.lst` (INI, `[Name]` sections, `Address`, `Port`, `ConnectionType`, optional `Username`, `Password`, `Comment`, `BPSRate`, `ScreenMode`): `Telnet` and `Raw` entries import (`TelnetS`, `SSH`, `RLogin`, `Modem`, `Serial`, `Shell` and others are skipped and counted); a `Password` value is moved into the Keychain, never into the directory. Cost if wrong: one key name in a SyncTERM file read wrongly; the user edits the entry.
12. **Table.** Columns Name, Address, Last Called, Calls, Notes, with tags shown under Name as a tooltip and in a Tags filter popup (All, each tag). Sorting by a column header is a view of the list; drag to reorder works on the stored order and is offered when no column sort is active. Search matches name, address, notes and tags, case insensitive.
13. **Hints.** Every control gets a tooltip (`toolTip` / `.help`); login scripts and macros get a (?) button with a short popover.

14. **Owner direction (received mid plan, from a screenshot of another terminal's text mode phonebook editor; used as a direction, nothing copied).** The directory and the entry editor are drawn in a retro text mode style with AnsiCore's renderer and fonts: CP437, a blue double line frame, yellow section headings, cyan labels, grey values, the current field highlighted, fully keyboard driven (Up/Down moves between fields, Enter goes to the next, Left/Right toggles or cycles a choice, Esc saves and goes back) with the keys in a footer; the mouse still works. A hint line under the fields explains the selected field in one or two plain sentences; every field has one (this is also the owner's hints request). Editor sections: Connection (name, host, port, protocol, tags, notes), Terminal (terminal type, default ANSI; size; font; encoding; iCE colours; simulated speed; Backspace; modem sound), Login (username, password masked, show password, auto login, the script steps, busy text), Capture, Macros; the footer shows last called and times called. The retro look is the only look: a second native AppKit table and SwiftUI editor would double the UI for little gain, so the native parts are a toolbar (with tooltips) above the retro view, open and save panels, and alerts. Ruling 12 still holds in the retro list: sort (S key or toolbar), tag filter (T), search (/), and reordering by Option-Up/Down or by dragging a row with the mouse. Fields the screenshot shows that AnsiView does not support (Sixel and iTerm2 inline images, IEMSI auto login, SSH key file and host key trust, TLS client certificates, RLogin users, shell command) get no controls; `ConnectionMode` stays an enum so SSH and others can join it in the later protocols plan, and they are listed under Needs owner / later. IEMSI is deferred (its EMSI_ICI handshake cannot be checked without a real IEMSI BBS, and the scope is already large). New pure files: `TextForm.swift` (a generic keyboard form and its screen), `EntryForm.swift` (the entry editor's fields, hints and apply), `DirectoryBrowser.swift` (the directory list's keys and screen). New entry fields: `terminalType` (default `ANSI`, sent first in the TERMINAL-TYPE cycle) and `iceColors` (the emulator shows bright backgrounds instead of blink). Cost if wrong: an owner who wants a native table as well gets it as a later task.

## Review Focus

- A password never reaches defaults, JSON, export, logs or the status line (test `passwordsNeverInJSON`, and the harness greps the defaults plist and export file for the test password).

- Migration from the plan 7 key does not lose entries and does not overwrite an existing directory (tests `migratesPlan7Book`, `existingDirectoryWins`).

## Final review

Opus reviewer, range ee1763b..6678320: no Critical. Important, all fixed test first in one pass: (1) a new entry (or an edit) with an empty password field deleted another entry's shared Keychain item; an empty password now removes the item only when this entry owned the key and nobody shares it; (2) moving a password to a new key removed the old item before writing the new one, so a Keychain failure lost it; the new item is now written first; (3) a dial session that gave up was released at once, leaving its "No answer" panel with dead buttons; it now lives until the panel closes; (4) an unreadable stored directory was silently overwritten by the next save, and one bad entry emptied the whole list; entries now decode one by one, and unreadable data is copied to `dialingDirectory.unreadable` first. Minors fixed in the same pass: capture on connect problems have their own status part (the login status no longer hides them); the busy matcher runs before the login script and only for dialed sessions; saving an edit keeps calls recorded while the editor was open; a capture folder whose bookmark cannot be made is not shown as chosen; SyncTERM passwords that cannot be saved are named in the import summary. Deferred minors: a stale bookmark is not refreshed (it still resolves; the user re-chooses the folder if it stops working); `marked` keeps ids of deleted entries (the count can be high until U); toolbar buttons send hotkeys, so pressing New while `/` search is active types into the search.
