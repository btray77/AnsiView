# AnsiView 2.0 Terminal Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the BBS terminal work with every family of BBS still reachable today: ANSI-BBS with the SyncTERM/CTerm extensions, VT100/VT220, Avatar, RIPscrip, PETSCII, ATASCII, Viewdata/Prestel, BBC Mode 7, Apple II and Amiga, plus telnet over TLS and a first bytes detector, chosen per entry in the dialing directory.

**Architecture:** Every emulation is a pure value type in AnsiCore that conforms to one protocol, `TerminalEngine` (feed bytes, take replies, give an `AnsiScreen`, map keys). The existing `TerminalEmulator` keeps the ANSI-BBS path and gains profiles (VT100, VT220, Amiga) and CTerm extensions only for sequences it used to ignore, so current users see byte identical screens (pinned by `TerminalRegressionTests`). Retro platforms draw with original bitmap fonts made in code (`PlatformFonts`), addressed by a new optional `AnsiCell.glyph` index, so the shared `AnsiRenderer` draws every platform. RIPscrip draws vector graphics on a 640x350 16 colour raster (`RIPCanvas`) shown under the text layer. The app's `TerminalViewController` holds `any TerminalEngine` made by `TerminalEngines.make`.

**Tech Stack:** Swift 5 mode, Swift Testing, Network.framework (TLS through `NWProtocolTLS` with a verify block), Security.framework (certificate summary), AppKit, XcodeGen.

**Spec:** the owner brief of 2026-10-30 ("I want to be able to work with ALL BBS's"), copied in the coordinator task; research and sources are in `docs/BBS-COMPAT.md`, section "Terminal".

## Global Constraints

- macOS 14 or later; AnsiCore imports no AppKit (CoreGraphics, Network, Security are fine).
- Never the em-dash character, anywhere.
- Do not change `CURRENT_PROJECT_VERSION` (coordinator override). Keep `App/SSHTransport.swift` untouched.
- ANSI-BBS behaviour byte identical for current users: `TerminalRegressionTests` (seeded streams and the 61 file TWSUPP corpus) must stay green unchanged; the file player corpus renders md5 identical to main.
- Fonts: bundle only fonts whose licence clearly allows redistribution; otherwise draw original look-alike bitmap fonts in code. Never copy ROM dumps. Record every decision in `docs/FONTS.md` and `Credits.md`.
- Real BBS connections: read only (connect, observe, never log in, never send credentials). Mask IPs in reports.
- New pure logic in AnsiCore with tests written and seen failing first.

## Review Focus

1. A BBS that sends a sequence split across packets in any emulation (PETSCII has no multi byte codes, but Viewdata ESC attributes, Avatar ^V sequences, RIP lines and CTerm queries do): each parser keeps state between `feed` calls. Test: every engine's fixture fed one byte at a time gives the same screen as fed whole.
2. A hostile or garbage stream (random bytes) in any emulation must never crash or grow memory without bound (RIP polygons with thousands of points, flood fill, huge repeat counts in Avatar ^Y). Test: seeded random streams of 200 KB into every engine; RIP point and repeat caps.
3. Switching an existing entry: old directory JSON without the new fields loads with ANSI-BBS and plain telnet. Test in `TerminalTypeEntryTests`.
4. A TLS board with a self signed certificate: first use asks, the second connection is silent, a changed certificate is refused with a warning. Test: `KnownCertificates` and a local `openssl s_server` round trip.
5. Detection must never switch on its own: the detector only returns a suggestion, and ANSI art that happens to contain 0x93 or 0x7D is not flagged once ANSI escapes were seen. Test in `TerminalDetectorTests`.

## Rulings

1. Terminal type is a new field `emulation` (JSON key `emulation`); the old `terminalType` string stays as the TTYPE name sent first and is relabelled "Terminal name sent". Choosing a type in the form sets the TTYPE name, size and font defaults only when they still hold the previous type's defaults (same rule as ports).
2. Retro platforms put a glyph index in `AnsiCell.glyph` and keep a readable character in `code` (ASCII where one exists) so Copy gives text.
3. CTerm extensions live in every profile of `TerminalEmulator` because they only answer sequences that were ignored before.
4. Telnet over TLS is a toggle on telnet entries (`telnetSecure`, default port 992). Certificates the system trusts for the host connect silently; any other certificate uses trust on first use keyed by `host:port` and the leaf SHA-256.
5. Detection only suggests (a bar with Switch and Ignore); it looks at the first 2 KB of a session.
6. Sixel and iTerm2 images, IEMSI and TLS client certificates are attempted only after the ordered list (ANSI-BBS, VT, Avatar, PETSCII, ATASCII, Viewdata, TLS, detection, RIPscrip, rest) is done; what is not done is reported.

## Tasks

### Task 1: Terminal type, engine protocol, entry field
- Create `TerminalEmulation.swift`, `TerminalEngine.swift`; modify `BBSAddressBook.swift`, `EntryForm.swift`.
- Produces: `public enum TerminalEmulation: String, Codable, CaseIterable { ansiBBS, vt100, vt220, avatar, ripscrip, petscii64, petscii128, atascii, viewdata, mode7, appleII, amiga }` with `label`, `defaultColumns`, `defaultRows`, `terminalNames: [String]`, `defaultFontName`; `public protocol TerminalEngine` (`columns`, `rows`, `cursor`, `cursorVisible`, `changeCount`, `bells`, `scrollbackCount`, `font: BitmapFont?`, `feed`, `takeReplies`, `resize`, `clearScrollback`, `screen(scrollOffset:)`, `bytes(for:backspaceSendsDelete:)`, `text(_:)`, `overlay() -> CGImage?`, `click(x:y:) -> [UInt8]`); `TerminalEngines.make(_:columns:rows:encoding:iceColors:) -> any TerminalEngine`; `BBSEntry.emulation`, `BBSEntry.telnetSecure`.
- Tests `TerminalTypeEntryTests`: old JSON decodes to `.ansiBBS`/false; round trip; form choice applies defaults (PETSCII gives 40x25 and TTYPE first name); `TerminalEngines.make(.ansiBBS...)` is a `TerminalEmulator` whose digest equals the plain emulator for seed 1.

### Task 2: VT100/VT220 and CTerm extensions in TerminalEmulator
- Tests `VTTerminalTests`, `CTermTests`: `ESC ( 0` then `lqk` draws CP437 0xDA 0xC4 0xBF in VT100 but not in ANSI-BBS; SO/SI with G1; DECCKM `CSI ?1h` makes Up send `ESC O A`; DA reply VT100 `CSI ?1;2c`, VT220 `CSI ?62;1;6c`; CTerm `CSI < c` reply, `CSI = 1 n`/`CSI = 2 n` replies per cterm.txt, `CSI ?33h` iCE on, `CSI 0;n SP D` font select reported, `CSI = 255 h` doorway mode makes keys send NUL plus scan code; origin mode `CSI ?6h`; regression digests unchanged.

### Task 3: Avatar engine
- Tests `AvatarTerminalTests`: `^V^A` attribute, `^Y` repeat (capped at the line), `^V^H` goto, `^L` clear, AVT/0+ `^V^J` scroll area, sequences split byte by byte.

### Task 4: Platform glyph support and original fonts
- `AnsiCell.glyph: UInt16?`, `BitmapFont(name:width:height:glyphs:)` public with any glyph count, renderer uses `glyph` first. Tests: render of a cell with glyph index 300 uses that glyph; corpus render md5 unchanged (`ansirender` check); fonts have the documented counts (C64 2x128, ATASCII 128, teletext alpha 96 plus 128 mosaics plus double height halves, Apple II 128, Topaz 256).

### Task 5: PETSCII engine (C64, C128 80 column)
- Tests `PETSCIITerminalTests`: 0x93 clears, colour codes give the C64 palette, RVS on/off, 0x0E switches to lower case set, cursor codes, insert/delete, 40 column wrap and scroll, key map (Up 0x91, F1 0x85, Home 0x13, Shift Home 0x93, Backspace 0x14), typed text case swap in lower case mode.

### Task 6: ATASCII engine
- Tests: 0x7D clear, 0x9B EOL, cursor 0x1C-0x1F, inverse high bit, 0x1B literal next, insert/delete line and char, key map (Return 0x9B, Backspace 0x7E).

### Task 7: Teletext engine (Viewdata and Mode 7)
- Tests: ESC A red alpha, mosaic contiguous/separated glyphs, hold mosaics, double height bottom row, conceal hidden until reveal, flash sets blink, cursor wraps at col 40 and row 24, Viewdata `_` sends `#`, Mode 7 VDU 31 x y.

### Task 8: Apple II and Amiga
- Apple II: 40x24 text, inverse Ctrl-O/Ctrl-N, 80 column firmware codes, upper case option. Amiga: `TerminalEmulator` profile with Latin-1, LF as CR LF, 0x9B as CSI, `CSI 0 SP q` window report, Topaz-like font, Amiga palette.

### Task 9: Detection
- `TerminalDetector.suggest(_ bytes: [UInt8]) -> TerminalEmulation?`: 0x93 early with no ESC means PETSCII, 0x7D with 0x9B means ATASCII, `!|` RIP, ESC A..Z attribute pairs with 0x0C means Viewdata, `^V^A` means Avatar.

### Task 10: Telnet over TLS
- `KnownCertificates` (file `known_tls_hosts`, lines `host:port sha256 subject`), `CertificateVerifying` protocol, `TCPTransport(tls:verifier:)` using `sec_protocol_options_set_verify_block`. Tests: store checks, and a local `openssl s_server` self signed round trip (first use asks, then trusted, changed refused).

### Task 11: RIPscrip 1.54
- `RIPParser` (lines starting `!|`, `\` continuation, MegaNum), `RIPCanvas` (line, rect, bar, circle, oval, arc, pie, bezier, polygon, fill poly, flood fill with a pixel budget, line styles, fill patterns, palette, text with an original 8x8 font scaled for fonts 1 to 4), mouse regions and buttons returning host commands. Tests with original fixtures.

### Task 12: App wiring and harness proof
- TerminalViewController holds `any TerminalEngine`; font and window size from the engine; RIP overlay drawn under text; clicks; detection bar; certificate prompt; entry editor field. Harness PNGs per emulation from fixtures and from read only live captures.

### Task 13: Docs, review, fixes
- `docs/BBS-COMPAT.md` Terminal section, `docs/FONTS.md`, `Credits.md`, README, checklist; opus whole branch review; Critical and Important fixed test first.
