# AnsiView 2.0 Plan 6: Creation (ANSI Editor and Image Import) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap items 25 and 26: a TheDraw style ANSI editor in the macOS app (new art, edit any opened art as a copy, save as `.ans` with SAUCE, `.bin`, `.xb`) and an image to block character ANSI converter (File > Import Image... and `ansirender --from-image`).

**Architecture:** The editing model is pure and lives in AnsiCore: `EditCanvas.swift` (the cell grid, half block painting, regions, fill, resize, iCE conversion), `CanvasEditor.swift` (cursor, colours, selection, block sets, clipboard regions, undo through Foundation's `UndoManager`), `ArtWriter.swift` (ANSI, BinaryText and XBin serialisation plus `Sauce.encoded()`), `ImageToAnsi.swift` (ImageIO loading, resampling, quantising, dithering, cell building). The app adds `App/AnsiEditor.swift` (window controller, view controller, palette bar, canvas view: a thin AppKit layer that forwards to `CanvasEditor`) and `App/EditorSheets.swift` (SAUCE, canvas size and image import option sheets). The editor is app only (not in `Shared/`, which the Quick Look extension compiles). `Tool/main.swift` gains `--from-image`.

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, AppKit, SwiftUI commands, ImageIO / CoreGraphics, XcodeGen.

**Spec:** `docs/ROADMAP-2.0.md` items 25 and 26, plus the coordinator's scope notes for plan 6 (copied into the rulings below).

## Rulings

1. **Cell model.** `EditCanvas` stores `AnsiCell` (RGB colours) so truecolor imports, custom XBin/ADF palettes and VGA art all edit without loss. Colour pickers offer the 16 VGA colours. The canvas has `columns` (1...1000, the same limit as SAUCE and XBin), a height of at least 1 that grows when the cursor or a paste goes below the last row (up to `AnsiTerminal.maxRows`, 1500), `iceColors`, `font` and SAUCE metadata (title, author, group, comments, fontName, flags). New art: 80 x 25, iCE off, `IBM VGA`.
2. **iCE colours.** With iCE on, a background may be any VGA colour; with iCE off, the background picker offers 0 to 7 only and `CanvasEditor` darkens a bright background to its dark half (index - 8) when set. Toggling iCE converts cells exactly the way the bytes would read: on: blinking cells become bright background, not blinking; off: bright VGA backgrounds become dark background plus blink. Undoable.
3. **ANSI writer.** CP437 bytes, CRLF after each row, trailing default blank cells and trailing blank rows dropped (no viewer keeps them; AnsiView's terminal trims them too). Colours: a VGA foreground is `3x` plus `1` for 8 to 15; a VGA background 0 to 7 is `4x`; 8 to 15 is `5;4x` with iCE on, and `48;2;r;g;b` with iCE off (only reachable from imports or old files); anything not in the VGA palette is `38;2` / `48;2`. Blink with iCE off is `5`. An SGR is emitted only when the attributes change; turning bold or blink off writes `0` and restates the rest. Codes that are control characters to a terminal (0x00, 0x07, 0x08, 0x09, 0x0A, 0x0D, 0x1A, 0x1B) are written as `TextConvert.lookalikes` (0x00 as space, the others as the plan 4 lookalikes). UTF-8 only cells (`scalar` set) write their `code` ("?"). SAUCE: data type 1, file type 1, TInfo1 columns, TInfo2 rows written, flags = iCE bit plus the original letter spacing and aspect bits, font name from the canvas (default `IBM VGA`), date = save date, file size = byte count before the EOF marker, comments kept. Cost if wrong: one file.
4. **Binary writers.** `.bin`: char/attribute pairs for every row (height kept exactly), SAUCE data type 5, file type columns / 2; an odd width is padded with one blank column (BinaryText cannot store odd widths). `.xb`: header `XBIN 0x1A`, width, height, font height 16, flags iCE (0x08) only, uncompressed pairs, SAUCE data type 6, TInfo1 width, TInfo2 height. Attribute = fg | bg << 4 | 0x80 for (iCE and bright background) or blink; a colour not in the VGA palette becomes the nearest VGA colour (squared RGB distance; a background with iCE off is limited to 0 to 7). Embedded fonts and palettes are not written; the canvas renders with `BitmapFont.named(fontName)`, so what you see is what is saved.
5. **Pixel identity.** A saved file re-opened through `ArtFile` + `AnsiAnalysis` + `AnsiRenderer` renders byte identical to `AnsiRenderer.render(canvas.screen(trimmed:))`, where `.ans` compares against the trimmed screen (ruling 3) and `.bin`/`.xb` against the full canvas. Proven by tests over a canvas with all 16 x 16 colour pairs, blink, truecolor, half blocks, every non control CP437 code and a 100 column width.
6. **Undo.** `CanvasEditor` owns an `UndoManager`; every mutating command registers one undo that restores the whole previous `EditCanvas` (a value type: unchanged rows share storage, so a step costs one outer array plus the changed rows). A mouse stroke (mouse down to mouse up) is one undo group. The window returns this manager from `windowWillReturnUndoManager`, so Edit > Undo / Redo work.
7. **Block sets.** Ten TheDraw / PabloDraw style sets of ten characters, F1 to F10 insert the current set's character at the cursor, Option-F1 to Option-F10 (and a popup) choose the set, default set 6 (blocks). Sets (CP437 codes): 1 `218 191 192 217 196 179 195 180 193 194`, 2 `201 187 200 188 205 186 204 185 202 203`, 3 `213 184 212 190 205 179 198 181 207 209`, 4 `214 183 211 189 196 186 199 182 208 210`, 5 `197 206 216 215 232 233 155 156 153 239`, 6 `176 177 178 219 223 220 221 222 254 250`, 7 `1 2 3 4 5 6 240 14 15 32`, 8 `24 25 30 31 16 17 18 29 20 21`, 9 `174 175 242 243 169 170 253 246 171 172`, 10 `227 241 244 245 234 157 228 248 251 252`. These are PabloDraw's defaults as recalled (inferred, not checked against PabloDraw's source here); cost if wrong: a table.
8. **Half block painting.** A cell's two pixels: `▀` (223) top fg, bottom bg; `▄` (220) top bg, bottom fg; `█` (219) both fg; space, NUL, 255 both bg; any other character both bg (painting replaces it). Painting colour c into one half then re-encodes: equal halves give `█` fg c (bg kept); otherwise `▀` fg top / bg bottom when bottom can be a background, else `▄` fg bottom / bg top when top can be, else `▀` with the bottom darkened (index - 8). Blink is cleared. Left button paints the foreground colour, right button the background colour.
9. **Typing.** Characters map through `CP437.code(for:)`; unmappable characters are ignored. Typing writes at the cursor with the current colours and moves right; at the last column the cursor wraps to the next row. Return goes to column 0 of the next row, Backspace moves left and clears, Delete clears the cell (or the selection), arrows move (Shift extends the selection), Home/End go to the row's ends. Moving down past the last row adds a row.
10. **Clipboard.** Copy puts the selection on the pasteboard twice: a private type `com.traynham.ansiview.cells` (the region as `.xb` bytes without SAUCE, so colours and characters survive) and plain UTF-8 text (`TextConvert.utf8Text`). Paste prefers the private type and pastes the rectangle at the cursor; otherwise plain text pastes line by line from the cursor with the current colours. Cut = copy + clear. Paste is one undo.
11. **Fill.** Art > Fill Selection with Character fills the selection with the most recently used block set character (default `█`) in the current colours; Art > Fill Selection with Colour sets fg and bg and keeps characters. No selection: the whole canvas.
12. **Opening for editing.** File > New ANSI Art (Cmd-N) opens an untitled 80 x 25 editor. File > Edit Art (Cmd-Shift-D) opens the focused art window's final screen as an untitled copy ("<name> (edited)"); animated files edit their final frame. iCE is on when the file says so or any cell has a bright VGA background. The first Save always shows the save panel (format popup ANSI / BinaryText / XBin, defaulting to the original's kind: `.bin` and `.xb` keep theirs, everything else `.ans`); later saves write to the chosen URL. Closing with unsaved changes asks Save / Don't Save / Cancel.
13. **Image import (item 26).** `ImageToAnsi.Options`: `columns` (1...1000, default 80), `mode` (`.halfBlocks` default, `.fullBlocks`, `.shades`), `palette` (`.vga16` default, `.trueColor`), `dither` (`.none`, `.floydSteinberg` default, `.ordered` 4x4 Bayer), `iceColors` (default true), `aspectCorrection` (default true). Images load with ImageIO (`CGImageSourceCreateImageAtIndex` index 0, so GIF gives its first frame), are drawn on black (transparency becomes black) into an sRGB RGBA buffer at the sample size with high quality interpolation. Sample grid: `columns` wide; height `round(imageHeight / imageWidth * columns * f)` where f is 1 for half blocks (two samples per cell, cells = ceil(samples / 2)) and 0.5 for full blocks and shades (one sample per cell), and with aspect correction off f doubles. Half blocks: each pair is quantised and encoded as in ruling 8 with fg/bg the two colours (iCE off: a bright bottom becomes `▄` or is darkened). Full blocks: `█` fg c, bg black. Shades: for each cell the best of space/`░`/`▒`/`▓`/`█` (coverage 0, 0.25, 0.5, 0.75, 1) with any fg and allowed bg, by squared distance of the mix to the target. Truecolor: half blocks are exact `▀` fg top / bg bottom, full blocks and shades are exact `█`; dithering does not apply. Errors from Floyd-Steinberg diffuse 7/16, 3/16, 5/16, 1/16 over the sample grid; ordered dither adds (Bayer/16 - 0.5) * 64 to each channel before quantising. Result: an `EditCanvas` (title = file name without extension), opened in the editor by the app and written as `.ans` with SAUCE by the CLI.
14. **CLI.** `ansirender --from-image <file> [--width N] [--mode half|full|shade] [--palette vga|truecolor] [--dither none|fs|ordered] [--ice|--no-ice] [--no-aspect] [-o out.ans]`; without `-o` (or `-o -`) the `.ans` bytes go to stdout; unreadable image exits 1, bad option exits 2.

## Review Focus

- An opened file wider than 1000 columns or taller than 1500 rows, or an empty file: the editor clamps and opens (test `canvasFromHugeAndEmptyScreens` in Task 1).
- Pasting plain text that would run past the right edge or bottom: clipped at the edge, rows grow up to the limit, nothing crashes (test `pastePlainTextClipsAtEdges` in Task 3).
- Resizing the width smaller with the cursor and selection beyond it: both are clamped (test `resizeClampsCursorAndSelection` in Task 3).
- A transparent or 1 x 1000 pixel image, or a 1 column width: the converter returns at least one cell row and never divides by zero (test `degenerateImages` in Task 5).
- Saving `.bin` with an odd width, or `.xb`/`.bin` with truecolor cells: padded / nearest VGA, and re-opens (tests `binOddWidthPads`, `binaryNearestVGA` in Task 2).
