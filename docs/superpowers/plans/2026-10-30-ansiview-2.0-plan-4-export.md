# AnsiView 2.0 Plan 4: Export and Conversion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap items 20 to 24: batch export of a folder or art pack (app and CLI), export controls (frame rate, GIF palette, size limits), HTML export, conversion to modern terminal ANSI and plain CP437 text, and a share sheet.

**Architecture:** Pure logic goes in AnsiCore: `TextConvert.swift` (modern ANSI, CP437 and UTF-8 text), `HTMLExport.swift` (HTML document), `GIFEncoder.swift` (indexed render, palette choice, LZW GIF writer with changed rectangles), `SizeLimit.swift` (scale for a maximum size, attempt ladder for a maximum byte count), `BatchNaming.swift` (output file names). Encoders that need libwebp or AVFoundation stay in `App/AnsiExport.swift`, which gains `ExportSettings` and a single `AnsiExporter.export(...)` entry point. `App/BatchExport.swift` runs a batch (shared by the app and `ansirender`). `ArtCollection` moves from `App/Slideshow.swift` to `App/ArtCollection.swift` so the CLI can list folders and packs. The app gains `App/BatchExportUI.swift` and `App/ShareUI.swift`; `App/AnsiExportUI.swift` gains the new controls and a text export panel.

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, AppKit, ImageIO, libwebp, AVFoundation, WebKit (verification harness only), XcodeGen.

**Spec:** `docs/ROADMAP-2.0.md` (items 20 to 24) plus the coordinator's notes for plan 4.

## Rulings

1. **Modern ANSI (item 23).** One line per row, rows end with `ESC[0m` then `\n`, no cursor movement, UTF-8 text with CP437 mapped through `CP437.unicode` (control code glyphs too, so no control bytes reach the terminal). SGR is emitted only when the colour or blink changes. Trailing cells equal to the default cell (space, light grey on black, no blink) are dropped; trailing empty rows are dropped. Two colour modes: `trueColor` (`38;2;r;g;b` / `48;2;r;g;b`) and `xterm256` (`38;5;n`): the 16 VGA colours use indexes 0 to 15 (AnsiView reads those back as the exact VGA values), any other colour the nearest of indexes 16 to 255 by squared RGB distance. Blink is `5` / `25`. NUL cells become spaces. Cost if wrong: one function.
2. **Plain text (item 23).** CP437 bytes, trailing spaces trimmed, CRLF line ends (DOS text). Cell codes that would be read as control characters (0x00, 0x07, 0x08, 0x09, 0x0A, 0x0D, 0x1A, 0x1B) become lookalikes: 0x00 space, 0x07 0xF9, 0x08 0xDB, 0x09 `o`, 0x0A 0xDB, 0x0D 0x0E, 0x1A `>`, 0x1B `<`. A UTF-8 variant (`utf8Text`) uses `CP437.unicode` and LF. Cost if wrong: a table.
3. **Round trip.** Converting to modern ANSI then `ArtFile(data:fileExtension:"ans")` with the same column count gives the same cells (character, fg, bg, blink, scalar) after NUL is normalised to space; with `xterm256` this holds for VGA colours, with `trueColor` for every colour. Plain CP437 text round trips characters except the eight codes in ruling 2.
4. **HTML (item 22).** A complete HTML5 document: `<pre class="ansi">` with runs of equal attributes in `<span>`s, `&`, `<`, `>` escaped, CP437 mapped to Unicode. Styles: `classes` (VGA colours as `.f0` to `.f15` / `.b0` to `.b15` in a `<style>` block, other colours inline) or `inline` (every span has `style="color:#rrggbb;background:#rrggbb"`). Blink is a `blink` class with a CSS `steps` animation (0.92 s period, matching the player's 0.46 s interval). Font: by default the bundled Px437 TTF matching the art's font height (16: IBM VGA 8x16, 14: EGA 8x14, 8: EGA 8x8, others VGA) embedded as a base64 `@font-face` with a credit comment (Px437 by VileR, int10h.org, CC BY-SA 4.0); `font-size` equals the font height in px and `line-height: 1`, so cells are exact. Without the font, the `pre` uses `ui-monospace, Menlo, monospace` (block characters may show gaps). 9 pixel mode and the 4:3 aspect are not reproduced. Cost if wrong: one function and a CSS block.
5. **GIF palette (item 21).** `GIFPalette` modes: `automatic` (default): the exact colours of all frames when they number at most 255, written by AnsiView's own GIF encoder; `vga16`: the 16 VGA colours, other colours mapped to the nearest; `system`: the ImageIO encoder used before this plan. More than 255 colours in `automatic` falls back to `system`. AnsiView's encoder writes a global colour table (smallest power of two holding the palette plus one transparent entry), the NETSCAPE loop extension, and for each frame only the bounding rectangle of changed pixels; inside it unchanged pixels are encoded as the transparent index when that makes the frame smaller (both encodings are tried). Fractional scales (below 1x, from size limits) always use `system`, because resampling makes new colours. Cost if wrong: the encoder is self contained; `system` stays available.
6. **Frame rate (item 21).** `AnsiFrameSequence.make` already samples at `fps`. Choices 5, 10, 15 (default), 20, 30 fps in the app; any 1 to 60 in the CLI.
7. **Size limits (item 21).** `SizeLimit.none`, `.maxBytes(Int)`, `.maxPixels(width:height:)`. Max pixels: the requested integer scale if it fits, else the largest integer scale that fits, else render at 1x and resample down (high quality) to fit exactly. Max bytes: try the requested settings, then walk a ladder ordered by quality: for each scale (requested down to 1, then 0.75, 0.5, 0.25 of 1x), each frame rate in (requested, 10, 5) not above the requested; skip a rung whose pixel ratio predicts more than 1.25 times the target from the last measurement. The first result within the target wins; if none fits, the smallest result is kept and reported as over the limit (not an error). App presets: None, 1 MB, 2 MB, 5 MB, 10 MB, Fit 800 x 600, Fit 1280 x 720, Fit 1920 x 1080. MB is 1,000,000 bytes.
8. **Batch (item 20).** File > Batch Export... (Option Command E). In a gallery window it exports the selected pieces, or all when none is selected (the gallery allows multiple selection); elsewhere it first asks for a folder or ZIP art pack. Then an open panel asks for the output folder (Create Folder allowed) with an accessory view: Format (PNG, JPEG, WebP, GIF, Animated WebP, MP4 Video, HTML, ANSI (24 bit), ANSI (256 colours), CP437 Text, UTF-8 Text), Size, Speed, Frame Rate, GIF Palette, Size Limit. Stills export the finished art; animation formats export the playback at the speed (static art gives a one frame animation held 3 s). A progress sheet shows "n of N: name" with a Cancel button; cancel stops after the current frame and keeps finished files. Per file errors are collected; the end alert says "Exported X of N files" and lists failures and over limit files (first 20, then "and N more"), with a Show in Finder button. Output names: the piece's name with its extension replaced (`/` and `:` become `_`); a name already used in this batch or present on disk (case insensitive) gets " 2", " 3" before the extension. Nothing is overwritten unless `overwrite` is set (CLI `--overwrite`). Cost if wrong: re-runs accumulate numbered copies.
9. **CLI.** New forms, options in any order before the positional arguments:
   - `ansirender --export <format> [options] <input> <output>`
   - `ansirender --batch <format> [options] <output-folder> <input>...` (inputs are files, folders or `.zip` packs; exit 1 if any file failed)
   - `ansirender --convert html|ansi|ansi256|text|utf8 [--inline] [--no-font] <input> [output]` (output `-` or missing writes to stdout)
   - options: `--scale N`, `--baud N`, `--fps N`, `--palette auto|vga|system`, `--max-bytes N`, `--max-size WxH`, `--overwrite` (batch).
   - formats: `png jpeg webp gif awebp mp4 html ansi ansi256 text utf8`. Existing forms are unchanged.
10. **Share (item 24).** File > Share Image... and File > Share Animation... (no toolbar: SwiftUI document windows have none and adding one changes window sizing). Share Image writes the frame on screen as a 2x PNG named after the art into a fresh folder in the temporary directory; Share Animation writes a 1x GIF at the file's speed behind the progress sheet. Then `NSSharingServicePicker` shows from the top centre of the art view. The temporary folder is removed when the app quits (it is inside the sandbox temporary directory).
11. **Single exports.** Export Animation gains Frame Rate, GIF Palette and Size Limit; Export Image gains Size Limit; File > Export Text... (Option Shift Command E) saves HTML, ANSI (24 bit), ANSI (256 colours), CP437 Text or UTF-8 Text of the frame on screen. The progress sheet gains a Cancel button.

## Review Focus

- Batch over a folder where a file cannot be read or rendered (zero byte file, unreadable entry): reported, the batch continues (Task 5 test `batchContinuesAfterFailure`).
- Two pieces with the same stem (`A.ANS`, `a.ice`) or an output file already on disk: no overwrite, numbered names (Task 5 test `namesNeverCollide`).
- Size limit that cannot be met (1 byte): smallest result kept and flagged, no endless loop (Task 4 test `ladderEndsWhenNothingFits`).
- HTML for art containing `<`, `&` and control code glyphs: escaped and mapped, no raw control characters (Task 2 test `escapesMarkup`).
- 24 bit art with more than 255 colours as GIF in automatic mode: falls back without crashing (Task 3 test `tooManyColoursHasNoPalette`).
