# AnsiView 2.0 Music Playback (viewer, terminal, export) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) with superpowers:test-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ANSI music that the music core already parses and synthesizes now plays where art is seen: in viewer windows in step with baud playback (foreground music holds the drawing, background music does not), in the BBS terminal as bytes arrive (SyncTERM behaviour, per entry mode), and in MP4 exports as an audio track. Quick Look stays silent.

**Architecture:** One pure scheduler in `Packages/AnsiCore/Sources/AnsiCore/MusicScheduler.swift`, clock injected (every call takes `at now: Double`):
- `MusicQueue`: one speaker. Sequences play in arrival order, each after the one before; foreground music holds the display until the queue has drained (SyncTERM drains the queue at the end of a foreground string). Pause and resume shift every time.
- `MusicPlaybackScheduler`: the file player's view. It knows each playable sequence's byte range, advances an `AnsiTerminal` in steps that stop at the end of the next sequence so its music starts the moment the cursor passes it, returns `MusicEvent`s for the audio output, and handles seek, pause, resume, stop, "play everything once" (Instant speed) and silent skipping (music off or muted).
- `TerminalMusicGate`: the terminal's view. Bytes pass through a `MusicStreamFilter`; bytes after a foreground sequence wait inside the gate until the music ends; background music never holds.
- `MusicPlaybackScheduler.audioNotes(_:)` turns scheduled music into one timeline for export.

The app side: a `MusicOutput` protocol in `Shared/AnsiPlayer.swift` (no AVFoundation there, the Quick Look extension compiles that file), `App/ViewerMusic.swift` (`AudioMusicOutput`, an AVAudioPlayerNode queue), the player hooks in `Shared/AnsiPlayer.swift`, Playback menu items in `App/AnsiViewApp.swift`, a small hook in `App/BBSTerminal.swift` backed by `App/TerminalMusic.swift`, `BBSEntry.musicMode` plus an entry form field, MP4 audio in `App/AnsiExport.swift` and a checkbox plus note in `App/AnsiExportUI.swift`.

**Tech Stack:** Swift 5 mode, Swift Testing, AppKit, AVFoundation (AVAudioEngine, AVAssetWriter), XcodeGen.

**Spec:** Owner brief section 2, row "Playback during viewing and in the terminal" in `docs/STUDIO-CHECKLIST.md`, the coordinator's task message, and the "Player integration interface" of `2026-10-30-ansiview-2.0-music-core.md`.

## Rulings (each with its cost if wrong)

1. **One speaker queue.** All music of a stream plays in order, each sequence starting when the previous one ends (GW-BASIC's and SyncTERM's single note queue). A foreground sequence holds the display until the queue is empty, so foreground music after background music waits for both. Cost if wrong: background music immediately followed by foreground music would, on a terminal that mixes voices, start sooner; no historical terminal did that.
2. **The display holds on the clock, not on the audio callback.** The hold ends at `start + duration` on the player's clock; the audio node plays the same buffers back to back. Cost if wrong: audio start latency (about 10 to 30 ms) shows as drawing resuming that much before the last note ends.
3. **Music makes art playable in the app.** A file with playable music (and a music output) replays at the chosen speed with a scrub bar even when its art is not animated, so its music plays where it was sent. Without music output (Quick Look) or with Play ANSI Music off when the window opened, such a file is static as before. Cost if wrong: static art with music now draws at baud speed in app windows; Instant speed gives the old behaviour.
4. **Muted or off means ignored.** With Play ANSI Music off or the window muted, sequences neither sound nor hold the drawing (the scheduler skips past them silently). Turning music back on mid playback plays the sequences reached from then on. Cost if wrong: muting changes timing; someone wanting silent but historically timed playback cannot get it.
5. **Per window mute is not stored.** Play ANSI Music and Play Music at Instant Speed live in the shared defaults (like Modem Sounds); Mute This Window is per window and resets for each new window. Cost if wrong: a user who wants one file always muted has to mute it each time.
6. **Instant speed and Skip to End.** Opening or replaying at Instant plays the whole file's music once from the start (setting "Play Music at Instant Speed", default on), never holding. Skip to End, a seek, Replay, closing the window, halt (presentation take over) and switching to Instant mid playback stop the music. Reaching the end naturally does not stop it (background music sent at the end keeps playing). Cost if wrong: Skip to End is silent; a user expecting the rest of the tune must replay at Instant.
7. **Pause pauses the audio** (AVAudioPlayerNode pause keeps the queue) and shifts the scheduler's times by the paused span; resume continues the same note. Seek always stops audio; sequences before the new position are treated as already played (not replayed).
8. **Terminal.** The filter runs after the line pacer (music plays when its bytes would reach the screen at the simulated speed). While foreground music plays the pacer is not drained, so the backlog waits on the line and drawing resumes at the simulated speed afterwards. Per entry `musicMode` (Off, ESC[| only, BANSI = ESC[| and ESC[N (default, SyncTERM), All); `CSI = Ps M` from the BBS switches it unless the entry says Off. Play ANSI Music off silences the terminal too (music bytes are still removed from the screen per the entry mode). Capture files are written before the filter, so they keep the music bytes. Cost if wrong: a BBS relying on CTSAM to enable music when the user chose Off stays silent (intended).
9. **Export.** MP4 gets an AAC mono 44.1 kHz audio track when "Include ANSI music" is on (default on when the file has playable music, otherwise off and disabled). Video frames follow the same scheduler with a simulated clock, so foreground music holds frames in the video exactly as in the viewer; the final hold lasts until the music ends. At export speed Instant (not offered by the panel) the tune plays once from 0. GIF and animated WebP have no audio; the panel says so. Cost if wrong: an MP4 of a file with long foreground music is longer than before (it matches the viewer).
10. **Square wave** for the viewer and terminal (the PC speaker sound, the synth's default); the editor keeps its own waveform choice.

## Interfaces (produced by Task 1)

```swift
public struct ScheduledMusic: Equatable { sequence: MusicSequence; start: Double; holds: Bool; end: Double }
public enum MusicEvent: Equatable { case play(ScheduledMusic), pause, resume, stop }
public struct MusicQueue { scheduled; freeAt; holdUntil; pausedAt
  mutating add(_:at:holds:) -> ScheduledMusic; isHolding(at:); playing(at:) -> ScheduledMusic?; isActive(at:)
  mutating pause(at:) / resume(at:) / clear() }
public struct MusicPlaybackScheduler { init(_ sequences:); init(file: ArtFile); sequences; next; queue; hasMusic
  limit -> Int?; mutating reached(_ position:at:) -> [MusicEvent]
  mutating advance(_ terminal: inout AnsiTerminal, by bytes: Int, at now: Double) -> [MusicEvent]
  mutating seek(to:) -> [MusicEvent]; mutating skip(to:); mutating playAll(at:) -> [MusicEvent]
  mutating pause(at:) / resume(at:) / stop() -> [MusicEvent]; isHolding(at:); started: [ScheduledMusic]
  static audioNotes(_ scheduled: [ScheduledMusic]) -> [TimedNote] }
public struct TerminalMusicGate { init(mode:); plays: Bool; isHolding(at:); held: Int
  mutating feed(_ bytes:at:) -> (visual: [UInt8], events: [MusicEvent]); mutating reset(mode:) -> [MusicEvent] }
```
