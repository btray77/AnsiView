> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Genuine ANSI music (BASIC PLAY strings sent after `ESC [ M`, `ESC [ N` or `ESC [ |` and ended by 0x0E) in AnsiView: a stream scanner with byte offsets, a PLAY string parser and canonical serializer, a deterministic PC speaker style synthesizer, WAV and MIDI export, `ansirender --music`, and an ANSI Music Editor window (piano roll, text, library, import, export).

**Tech Stack:** Swift 5 mode, Swift Testing, AppKit, AVFoundation (AVAudioEngine), XcodeGen.

## Research and sources

1. **SyncTERM `cterm.txt`** (Synchronet repo, `src/conio/cterm.txt`; current version `https://syncterm.bbsdev.net/cterm.html`), section "ANSI" MUSIC and the entries for `CSI M`, `CSI N`, `CSI |`, `CSI = Ps M`:
   - History: "A programmer with either TeleMate or QModem (the first two programs to support "ANSI" music as far as I can tell) decided ... to add an "unused" ANSI code ... CSI M (Delete line) ... They defined "ANSI" music as: CSI M <music string> 0x0e". BananaCom later added `CSI N` to avoid the delete line conflict. CTerm added the standard compliant `CSI |`.
   - `CSI = Ps M` (CTSAM): 0 = only `CSI |`; 1 = `CSI |` and `CSI N`; 2 = `CSI |`, `CSI N` and `CSI M` ("In this mode, Delete Line will not be available").
   - `CSI M`: "If "ANSI" Music is fully enabled (CSI = 2 M), and no parameter is specified, performs "ANSI" music instead."
   - Allowed characters: `aAbBcCdDeEfFgGlLmMnNoOpPsStT0123456789.-+#<> ` and "If any character not in this list is present, the music string is ignored as is the introducing code."
   - First character rule: "If the introducing code is CSI M the first char is examined, and if it is a one of "BbFfLlSs" or if it is "N" or "n" and is not followed by a decimal digit, then the music string is treated as though an M is located in front of the first character." (This is how `ESC[MF` and `ESC[MB` work.)
   - T clamps to 32..255, default 120 (quarter notes per minute); O clamps to 6, default 4; L 1..64, default 4; "Dots are not cumulative, so "C.." is equivalent to "C.""; C notes of octaves 0..6: 65.406, 130.810, 261.620, 523.250, 1046.500, 2093.000, 4186.000 Hz.
   - Recommends following music with 0x0F (SI) because 0x0E shifts non ANSI-BBS terminals.
2. **SyncTERM `cterm.c` and `cterm_cterm.c`** (same repo): reset sets `music_enable=CTERM_MUSIC_BANSI` (so the terminal default is `CSI |` and `CSI N`), `tempo=120`, `octave=4`, `notelen=4`, `noteshape=CTERM_MUSIC_NORMAL`, `musicfore=TRUE`. `cterm_handle_ansi_music` enters music only when `music_enable == CTERM_MUSIC_ENABLED && seq_param_count == 0`, otherwise DL. The first character rule runs for `CSI M` and `CSI |` (`music = 1`), not for `CSI N` (`music = 2`). Bytes are accumulated until byte 14; any byte not in the allowed set clears the buffer and leaves music mode. Normal articulation pauses `duration/8`, staccato `duration/4`, legato 0. Duration is `240000/tempo/notelen` ms (dotted `360000/...`). `<` and `>` clamp to 0..6. Out of range notes play silence. Foreground strings drain audio before the parser continues; background strings do not. Tempo, octave, length and articulation persist between music strings.
3. **Microsoft GW-BASIC source** (`github.com/microsoft/GW-BASIC`, `GWSTS.ASM`, PLAY/SOUND section, released by Microsoft in 2020): `NOTTAB` holds octave 6 frequencies (C 4186 ... A 7040 ... B 7902 Hz) "DIVIDED DOWN BY POWERS OF TWO TO GET ALL OTHER OCTAVES"; `O` 0..6; `N` 0..84 ("NOTE 0 IS PAUSE", `DEC AX ;MAP TO 0..83`, so N1 is C of octave 0); `L` 1..64; `T` 32..255; `P` 1..64 (P0 does nothing); per note length digits 0 (none) to 64; dots iterate ("Duration = Duration * 1.5", loop `PLYDOT`, so dots are cumulative); MN 7/8, MS 3/4, ML 1/1 ("pause after note is 1/8 or 1/4"); MF default, MB background; `SNDINI`: T120, MN, MF, L4, O4; `NOTXLT` rejects `C-`, `B#`, `E#`, `F-` (Illegal function call). Duration unit: 96000/(T*length) ticks of 2.5 ms, i.e. `240/(T*L)` seconds.
4. **PDS 7.0 / QBasic PLAY references** (secondary): same ranges; QBasic help says "Middle C is at the beginning of octave 3" and its SOUND table labels 523.25 Hz middle C. The GW-BASIC code puts octave 3 C at 4186/8 = 523.25 Hz, so the manuals' "middle C" is 523.25 Hz, one octave above modern middle C; SyncTERM's table agrees with the code.

## Rulings (compatibility decisions, each with its cost if wrong)

1. **Pitch.** Semitone index `s = octave*12 + note` (C=0 ... B=11), 0..83. Frequency `7040 * 2^((s - 81)/12)` Hz (equal temperament anchored to GW-BASIC's A of octave 6 = 7040 Hz; gives O0 C 65.406, O4 C 1046.50, O4 A 1760 Hz, matching SyncTERM's table). We do not reproduce GW-BASIC's integer division and PIT divisor rounding (a few cents). Cost if wrong: pitch a few cents off, inaudible in practice.
2. **Durations.** Slot = `240/(T*L)` s, times 1.5 per dot. Sounding part: MN 7/8, MS 3/4, ML full; the rest is silence. Rests (P, N0, invalid notes) are silent for the whole slot.
3. **Dots.** Cumulative (GW-BASIC code) by default; `PlayDialect.syncterm` makes them non cumulative. Cost if wrong: a rare `C..` lasts 2.25 instead of 1.5 beats; switchable.
4. **Tolerance (never an error).** Values clamp like SyncTERM: T to 32..255, O to 0..6, L and per note length to 1..64 (0 and missing mean "use L"); `N` above 84 or a note shifted outside 0..83 by sharps/flats plays silence for its slot; `C-` is B of the octave below and `B#` is C above (semitone arithmetic, SyncTERM) instead of GW-BASIC's error; repeated `#`, `+`, `-` stack; `P` without a number uses L (SyncTERM); `P0` is skipped (GW-BASIC); unknown characters in a PLAY string typed in the editor are skipped and reported as warnings. `X` (GW-BASIC substring execution) and `=variable` are not supported (no variables exist).
5. **Stream scanner (SyncTERM model).** Modes: `off` (nothing is music), `pipe` (`ESC[|` only, SyncTERM CTSAM 0), `bananaCom` (`ESC[|` and `ESC[N`, CTSAM 1, SyncTERM's terminal default), `all` (adds `ESC[M` with no parameters, CTSAM 2). `ESC[=0M`, `ESC[=1M`, `ESC[=2M` inside the stream switch modes unless the mode is `off`. `ESC[` + digits + `M` is always Delete Line. The body is the bytes after the final byte up to 0x0E; a byte outside the allowed set aborts the sequence (not played, its bytes are still removed from the display) and is then processed normally; end of stream before 0x0E is an unterminated sequence (not played, removed). The first character rule applies to `ESC[M` and `ESC[|`. Bodies are capped at 65536 stored characters (further allowed bytes are swallowed). Cost if wrong: an art file that uses `ESC[M` as delete line followed by text made only of music letters loses that text in the viewer (ANSI.SYS has no delete line, so art files rarely do this; none of the 61 corpus files contains any introducer).
6. **Viewer default mode `all`.** Art files were made for the BBS terminals that played `ESC[M` music (Qmodem, Telix, TeleMate era), and the file player already ignores Delete Line. The terminal integration (later plan) should default to `bananaCom` like SyncTERM, with a setting. Cost if wrong: see ruling 5.
7. **State persists between sequences** in one stream (SyncTERM and GW-BASIC both keep T, O, L, articulation and MF/MB). Each sequence records the state it started with.
8. **Foreground/background.** MF is the default. A sequence with any foreground note blocks the display until its music ends (SyncTERM drains at the end of the string); a background-only sequence plays while drawing continues. The scanner reports `blocksDisplay`; the player integration honours it.
9. **Removal from the visual stream.** `AnsiTerminal` skips sequences in place (positions keep their meaning), and `AnsiMusic.scan` also returns `visual` (the stream without music bytes). A 0x0F (SI) directly after the 0x0E belongs to the sequence (SyncTERM tells authors to send it; without this the viewer would print its CP437 glyph). A lone 0x0E or 0x0F elsewhere prints as before. Cost if wrong: none for files without music (md5 proof); a file that wanted a visible sun glyph right after music loses it.
10. **Synth.** 44100 Hz mono Float32. Square wave (PC speaker, phase reset to 0 at each note so renders are deterministic), amplitude 0.25; `soft` = sine plus 1/5 third harmonic with 5 ms attack and release. Sample boundaries come from cumulative times (`round(t * 44100)`), so long tunes do not drift. Render cap 600 s (bounded memory: 105 MB of Float32 at most); WAV is 16 bit PCM.
11. **MIDI (extra).** SMF type 0, 480 ticks per quarter, one tempo event of 500000 us (120 BPM, so 960 ticks per second and every T change is exact in time), program 80 (GM Square Lead), channel 0, velocity 100, MIDI note `s + 36` (O0 C 65.4 Hz = MIDI 36 C2). Rests are gaps.
12. **Canonical serializer.** `T`, `M?` and `O` emitted only when they change, `L` chosen as the most common length and changed when a run benefits, notes as letters with `#` sharps, explicit length suffix when different from L, dots as `.`, rests as `P<len>`; tokens separated by spaces; output always reparses to the same items. It never emits `<`/`>`, `N`, or flats.
13. **Piano roll model.** Monophonic (the language is). X axis is whole note fractions (not seconds, so tempo changes do not move notes). Adding a note past the end fills the gap with rests (greedy 1/1 ... 1/64); clicking inside a rest splits it; clicking a note changes its pitch; dragging the right edge sets the length to the nearest of 1..64 with 0 to 2 dots and later notes shift; delete turns a note into a rest of the same length and trailing rests are trimmed.
14. **Keyboard entry.** `a w s e d f t g y h u j k` = C C# D D# E F F# G G# A A# B C(next octave), `z`/`x` octave down/up, `space` rest, `1`..`7` set length 1, 2, 4, 8, 16, 32, 64, `.` toggles a dot for the next note. Notes enter at the end of the tune.
15. **Library.** `MusicLibrary` (Codable JSON, `{"version":1,"snippets":[{"name","play"}]}`) stored at the app container's `Application Support/AnsiView/MusicLibrary.json`. Bad data decodes as an empty library (the file is not overwritten until the user saves a snippet).
16. **Embedding.** `AnsiMusic.embed` inserts the escape sequence into a file's bytes at the start, the end of the art (before 0x1A and SAUCE), or after line N; the rest of the file is kept byte for byte and only the SAUCE FileSize field is patched. The app always writes a new file through a save panel.
17. **Escape form for export.** Default introducer `ESC[M` (understood by the 1990s terminals and by SyncTERM in full music mode), with `ESC[N` and `ESC[|` offered. If the PLAY string starts with a letter the first character rule would read as MB/MF/ML/MS/MN (B, F, L, S, or N not followed by a digit) and the introducer is `M` or `|`, a space is put first (space is an allowed character). A 0x0F follows the 0x0E when "Add SI after music" is on (default on, SyncTERM's advice).

## Player integration interface (for the later plan, not built here)

- `AnsiMusic.scan(_ stream: [UInt8], mode: MusicMode = .all, dialect: PlayDialect = .gwbasic) -> MusicScan`, where `MusicScan.sequences: [MusicSequence]` each with `offset` (index of ESC in `ArtFile.stream`), `length` (bytes through the 0x0E), `isTerminated`, `introducer`, `body`, `startState`, `items`, `notes: [TimedNote]` (times relative to the sequence), `duration`, `blocksDisplay`.
- `AnsiTerminal.position` and `MusicSequence.offset` share coordinates, because `AnsiTerminal` skips sequences in place. During baud-rate playback the player calls `advance(byteCount:)` as today; when `position` passes `sequence.offset + sequence.length` it starts that sequence's notes (`MusicSynth.render` or a scheduled AVAudioPlayerNode buffer) and, if `blocksDisplay`, holds further advances until `duration` has elapsed. Seeking backwards stops the audio. Skip to End plays nothing.
- The interactive terminal can use `MusicStreamFilter` (incremental: `mutating func feed(_ bytes: [UInt8]) -> (visual: [UInt8], finished: [MusicSequence])`), which survives sequences split across packets and keeps state between them.

## Review Focus

1. A sequence split across `advance(byteCount:)` calls during baud playback: the terminal must finish the whole sequence (like an escape sequence) and not print its tail. Test in Task 2 (`terminalSkipsMusicAcrossAdvanceCalls`).
2. Huge or hostile input (megabytes of `C`, deep dots `C.........`, `T0`, `N999`, binary garbage): no crash, bounded notes and bounded render. Test in Tasks 1 and 3 (fuzz).
3. A PLAY string whose first note is B, F, L, S or N exported with `ESC[M`: must keep the note. Test in Task 2 (`escapeKeepsLeadingNoteLetters`).
4. Embedding into a file with SAUCE and comments: SAUCE still parses with the new size and comments intact. Test in Task 2.
5. Mode switching by `ESC[=2M` in the stream and `ESC[2M` (Delete Line with a parameter) not starting music. Test in Task 2.
