## Rulings (each with its cost if wrong)

1. **Ask before acting on a detected start.** A ZRQINIT (`**^XB00`), ZRINIT (`**^XB01`), Kermit S packet or Kermit receiver NAK shows a bar above the status line; the bytes from the match on are held (not drawn, at most 64 KiB, after which the match is treated as a false positive and the held bytes are drawn). Receive starts the session with the held bytes; Choose files to upload opens the open panel (held bytes keep collecting meanwhile). Ignore draws the held bytes and sends nothing; matches of the same kind in the next 60 s are drawn without asking again, so a retrying `sz` does not nag. The entry's "Auto-accept ZMODEM downloads" skips the bar for `zmodemReceive` only. Cost if wrong: after Ignore the BBS's `sz` waits for its own timeout (the user may type Ctrl-X five times to stop it sooner, the hint says so).
2. **BINARY first on telnet.** Before a session starts on a telnet connection (telnet mode, or WebSocket with Telnet inside), the client sends `TelnetSession.requestBinary()` through its own session and the coordinator waits until both directions are on or 2 s pass. If not byte clean, the panel warns for every protocol except Kermit, ZMODEM gets `zmodemEscapeTelnet` and Kermit gets `kermitForceEighthBitPrefix`. BINARY stays on after the transfer. Cost if wrong: a BBS that misbehaves with BINARY left on needs a reconnect.
3. **Terminal is paused during a transfer.** Every received byte goes to the session only (no capture of transfer bytes, no login script, no busy matcher, no emulator). At the start the pacer backlog and bytes held by music are drawn at once with music silenced (a playing tune stops). Keys other than Escape are ignored; Escape and the panel's Cancel cancel. Ticks of the emulator release and music are skipped; the 10 Hz session tick runs. After the end the detector is reset and new bytes draw normally. Bytes in the same chunk after the protocol's last byte are consumed by the engine (it does not report how many it used), so they are not drawn (minor, deferred). Cost if wrong: one line of BBS prompt after a transfer may be missing until the BBS redraws.
4. **Pull mode with backpressure.** The terminal pulls `session.takeOutput(max: 16 KiB)` while fewer than 256 KiB are in flight; each chunk goes through `BBSClient.sendTransfer(_:completion:)` and the completion (TCP `contentProcessed`, WebSocket send completion, SSH write promise) frees its bytes and pulls again. `TransferFlow` holds the counting. Cost if wrong: a 256 KiB window limits a long fat path to 256 KiB per round trip (about 2.5 MB/s at 100 ms).
5. **Partial files.** Downloads use `DownloadsDirectorySink` with `keepPartialForResume` true only for ZMODEM; ZMODEM downloads set `resume` so a marked `.part` from an interrupted ZMODEM download is continued (offset shown). Every other protocol removes its partial on cancel or failure. Cost if wrong: a remote file that changed between attempts gives a corrupt resumed file (same trust as `lrz -r`; the SHA-256 is shown for checking).
6. **Downloads folder.** Per entry `downloadFolderBookmark` (+ `downloadFolderName`), else the app default (a bookmark in UserDefaults `transferDownloadFolder`), else an open panel starting in the real `~/Downloads` asks once and saves the default. Security scoped app bookmarks with the existing entitlements. Cost if wrong: one extra panel the first time.
7. **Protocol memory.** `BBSEntry.transferProtocol` (default ZMODEM) is preselected in Upload and Download and updated (saved to the directory) whenever the user picks another one. XMODEM downloads ask for the file name (XMODEM carries none); XMODEM uploads take one file.
8. **Transfer log.** Each session's log lines with a header (date, entry, protocol, direction, outcome) are appended to `Application Support/AnsiView/Transfer Logs/<entry id>.log` in the container; a file over 1 MiB keeps its newest half. Terminal > Transfer Log shows the focused terminal's entry log. Cost if wrong: none beyond disk.
9. **YMODEM-G upload** has no independent receiver (lrzsz `lrb` never asks for G); it is proven against `ansixfer receive ymodem-g` run by the test BBS and labelled so.

// TransferCoordinator (pure, no clock reads: every call takes now)
public enum TransferOfferKind { case download(TransferProtocolKind), upload(TransferProtocolKind) }
public struct TransferOffer: Equatable { kind: TransferStartDetector.Kind; text: String; acceptTitle: String }
public enum TransferCoordinatorAction: Equatable {
  case showOnScreen([UInt8]); case feedSession([UInt8]); case showOffer(TransferOffer); case hideOffer
  case requestBinary; case startSession(TransferRequest); case chooseUploadFiles(TransferProtocolKind)
}
public struct TransferRequest: Equatable { kind; direction; options: TransferOptions-relevant flags (escapeTelnet, eighthBit, resume); warning: String?; initialBytes: [UInt8] }
public struct TransferCoordinator {
  init(autoAcceptZmodem: Bool, usesTelnet: Bool)
  var state: State  // .idle, .offering(TransferOffer, held), .negotiating(...), .running, .choosingFiles
  mutating func received(_ bytes: [UInt8], at now: Double) -> [TransferCoordinatorAction]
  mutating func accept(at:) / ignore(at:) -> [Action]
  mutating func begin(kind:direction:at:) -> [Action]      // menu Download/Upload
  mutating func filesChosen(_ ok: Bool, at:) -> [Action]
  mutating func tick(at:byteClean:) -> [Action]           // BINARY wait
  mutating func binaryChanged(byteClean:at:) -> [Action]
  mutating func sessionFinished() -> [Action]; mutating func cancelPending() -> [Action]
  var isTransferActive: Bool  // keys blocked, terminal paused
}
public struct TransferFlow { init(window: Int = 256<<10, chunk: Int = 16<<10); inFlight; mutating func nextChunkSize() -> Int; mutating func sent(_:); mutating func completed(_:) }
