## Rulings (with cost if wrong)

1. **Discord colour mapping.** Discord's ` ```ansi ` blocks honour only SGR 0 (reset), 1 (bold), 4 (underline), 30 to 37 and 40 to 47; 24 bit and 256 colour codes are not shown, and the mobile apps show no colour at all (community guide by kkrypt0nn, gist a02506f3712ff2d1c8ca7c9e0aed7c06). Discord draws those codes in a Solarized style palette, not VGA, so a VGA colour is sent as the code whose ANSI hue it is (foreground: the low three bits in ANSI order; bright VGA colours 8 to 15 add bold, which is the only "bright" Discord has). 24 bit colours go to the nearest of the 16 VGA colours first. Backgrounds: black is left as Discord's own background (no code); others use 40 to 47 by hue, which Discord shows in its own (darker) background palette. The table is in `docs/CHAT-COLOURS.md`. Cost if wrong: colours look different from the art in Discord (they always will; Discord has 8 colours).
2. **Discord length.** A message holds 2,000 characters (4,000 with Nitro). The copy is made anyway; Copy As Discord shows the character count in a short alert when it is over 2,000 so the user can select less. Codes are written only when the colour changes, and trailing blanks are trimmed, to keep it short. Cost if wrong: one alert.
3. **Slack has no ANSI colour.** Slack's formatting help documents code blocks with no colour or ANSI support, so Copy As Slack writes a plain ` ``` ` block of the UTF-8 text (no escapes). Labelled "inferred from Slack's documentation" in the docs. Cost if wrong: Slack users miss colour they could have had.
4. **Wallpaper.** The picture is exactly the chosen screen's pixel size (`NSScreen.frame.size * backingScaleFactor`, or `WxH` on the command line). Centred: the art is drawn at the largest whole number scale that fits (at least 1; a piece taller than the screen is drawn at 1x and its top is shown), centred, on its own background colour (the colour of the art's top left cell, black when blank). Tiled: copies at the chosen scale (default 1) from the top left corner. "Set as Desktop Picture" (a checkbox, off by default) calls `NSWorkspace.setDesktopImageURL` for that screen with the saved file. Cost if wrong: a few lines of layout.
5. **MP4 modem sound.** With "Include modem sound" the video starts with the synthesized handshake (`ModemSound.handshake`, 6.39 s) over the empty screen, then the line noise loops while bytes arrive, then silence for the final hold. This is the timing the viewer uses (Playback > Modem Sounds), including line noise while foreground ANSI music holds the drawing (the viewer's sound stays in its streaming state then too). The modem sound is mixed with ANSI music when both are on (music starts after the handshake, as in the viewer). It is AnsiView's own synthesis, no recording. At baud 0 (instant) there is no line noise; the handshake plays and the art appears after it. Cost if wrong: an option on one export.
6. **App Intents** (Shortcuts): "Render ANSI Art to Image" (file in, PNG or JPEG out, scale 1 to 4) and "Convert ANSI Art to Text" (file in, format UTF-8 text, CP437 text, modern ANSI or HTML; returns a file and the text). Both run without opening a window (`openAppWhenRun = false`). Cost if wrong: two small types.
7. **AppleScript.** `AnsiView.sdef` adds a suite with `render <file> to <file> [in format "png|jpeg|gif"] [scale n]` and `convert <file> [to <file>] [in format "text|utf8|ansi|ansi256|html"]` (`in format`, because `as` is AppleScript's coercion keyword) (returns the text when no output file is given). The app is sandboxed; AppleScript file parameters carry sandbox extensions for the files named. Not run live (no osascript in this plan): the command classes are exercised in a harness. Cost if wrong: scripts get an error naming the file.
8. **Finder Quick Actions** are two app extensions (`com.apple.services`, no user interface, `NSExtensionServiceAllowsFinderPreviewItem`): "Convert to PNG" and "Convert to GIF". They run in their own sandboxed process; AnsiView does not open. Cost if wrong: two extension targets.
9. **Where Quick Actions write.** A sandboxed extension may read the files Finder hands it but not create files beside them. The converted file is written beside the original when the sandbox allows it, otherwise into the user's Downloads folder (`files.downloads.read-write`, the only extra entitlement), named like the original with the new extension (never overwriting: " 2", " 3" are added). Cost if wrong: files land in Downloads instead of beside the art (stated in the README).
10. **Art of the day** is off by default (View > Show Art of the Day in Menu Bar). The pick is deterministic for the calendar day: FNV-1a hash of `yyyy-MM-dd` over the library's records sorted by key (favourites and pieces rated 4 or more first when there are any), else the bundled samples. "Include 16colo.rs" (off by default, and only when the menu bar item is on) adds a daily 16colo.rs piece fetched through `SixteenColorsClient`'s single lane (at least 1 s between requests): year list, that year's packs, the pack, the file; each answer is cached so a day costs at most four requests. Cost if wrong: a different piece each day than the user might expect.
11. **Localization.** One String Catalog per target with user visible text (app, Preview, Quick Actions, saver). Strings are extracted by the compiler (`SWIFT_EMIT_LOC_STRINGS`, SwiftUI literals and `String(localized:)`) and synced into the catalogs with `xcrun xcstringstool sync`. English only. AppKit strings built with `String` (not `String(localized:)`) are not all converted in this plan; the count of extracted keys and the count of remaining plain literals are both reported. Pseudo-locale proof: the built app bundle's strings are looked up with `NSAccentuateLocalizedStrings` and `NSDoubleLocalizedStrings` set (Xcode's pseudolanguages) in a harness, and a menu rendered offscreen shows the accented text. Cost if wrong: translators need another extraction pass for the AppKit strings.
12. **Sixel** output: the finished art rendered at the chosen scale (default 1) through the indexed renderer with the GIF automatic palette (at most 256 colours; the art's own colours exactly), written as `ESC P 0;1;0 q "1;1;W;H`, colour registers `#n;2;r;g;b` in percent, six pixel bands with run length `!n`, `ESC \`. **Kitty:** the PNG sent with `ESC _ G a=T,f=100,m=1;<base64 in 4096 byte chunks> ESC \` (the last chunk `m=0`). `ansirender --sixel|--kitty [--scale N] <input>` writes to stdout. Cost if wrong: one encoder each.
13. **Screen saver** (`AnsiView.saver`, `ScreenSaverView`): plays every art file in a chosen folder (default: the bundled samples copied into the saver) in shuffled order at a chosen baud (default 9600), animation included, holds each finished piece for a chosen time (default 8 s), scrolls tall art like the viewer's terminal playback. Options sheet: folder, speed, hold time. It renders with AnsiCore's `AnsiTerminal` and `AnsiRenderer` (the app's player is a view controller with app hooks; the saver needs only a view). The saver is built and copied into the app's Resources; File > Install Screen Saver... opens it with the system (System Settings asks the user). The saver host on macOS 14+ (`legacyScreenSaver`) is sandboxed, so a folder outside the saver's container may not be readable: the samples are the fallback and the options sheet says so. Cost if wrong: the saver shows the samples instead of the user's folder.

## Review Focus

1. No extension gets `network.client`; Quick Look, thumbnail and Spotlight entitlements unchanged (`codesign -d --entitlements` on the built bundles).
2. Quick Action file writes: never overwrite, only beside the source or in Downloads.
3. MP4 audio and video stay in step (audio length equals video length within one frame; the 2100 Hz answer tone is inside the handshake window; line noise stops when the drawing stops).
4. The 16colo.rs part of art of the day makes no request unless both settings are on, and only through the shared lane.
5. Sixel output decodes back to the same pixels (decoder in the tests; ffmpeg's sixel decoder if present).
