- `Screen/RetroScreenEncoder.swift`: `RetroPlatform` (PETSCII C64, PETSCII C128, ATASCII, Viewdata) and an encoder that turns an `EditCanvas` into that platform's bytes by matching each cell's CP437 glyph against the platform font's glyphs (found by feeding every candidate byte to the platform's own terminal engine) and its colours against the platform palette. `TelstarFrame` wraps Viewdata bytes in a Telstar frame JSON (`content.type` "rawV").

The app adds a Settings window (SwiftUI `Settings` scene) with the Appearance picker, an `AppearanceController` that applies Retro to every window (dark aqua controls, DOS blue chrome, the bundled VGA font for status labels), Save As formats in the editor, Screen > Export for Retro Platform..., and a Terminal popup in Preview as Caller. `ansirender --save <format>` writes every save format.

## Research

- SAUCE 00.5 (https://www.acid.org/info/sauce/sauce.htm, fetched 2026-10-30): Character file types 0 ASCII, 1 ANSi, 4 PCBoard, 5 Avatar; ADF and IDF have no SAUCE type; PCBoard and Avatar store width and lines in TInfo1 and TInfo2.
- Synchronet (https://wiki.synchro.net/howto:petscii, custom:menu_files, ref:files and `prntfile.cpp`): PETSCII display files use `.seq`, width variants `name.40col.seq` and `name.80col.seq`; `menu()` picks `.seq` for a PETSCII terminal. No ATASCII display file type exists in Synchronet's documentation or `prntfile.cpp`.
- Telstar 2 wiki (https://github.com/johnnewcombe/telstar-2/wiki/Frames, FrameSchema): a frame is JSON with `pid` (`page-no`, `frame-id`), `visible`, and `content` (`data`, `type`); type `rawV` is 7 bit videotex (00-7F) with escaped attribute codes, trailing spaces replaced by CR LF, rendered as is.
- No local ADF, IDF, PCB, AVT or Wildcat files exist (searched the disk); the corpus round trip uses the 61 TWSUPP .ANS files and the 124 16colo.rs files in AnsiView's cache, converted to each format and back.

## Rulings

1. **ADF.** Always 80 columns (the format has no width): wider art is refused with a message, narrower art is padded. Always iCE (the reader shows the blink bit as a bright background): blinking cells of a non iCE canvas become bright backgrounds (reported). The 64 entry palette is the standard EGA palette with the art's 16 colours in ADF's slots. The font is the canvas's embedded font, else its named font when that is 8x16, else IBM VGA 8x16 (reported). No SAUCE (no SAUCE type exists for ADF); title, author and group are not kept (reported). Cost if wrong: a viewer that wants SAUCE on ADF shows no title.
2. **IDF.** Header 04 "1.4", x1 y1 0, x2 = width - 1, y2 = height - 1; runs `01 00 n 00 c a` for 4 or more equal pairs (and for a literal 01 00 pair); 8x16 font and 16 colour palette at the end. Always iCE; no SAUCE (as ADF). Cost if wrong: as ADF.
3. **ICE.** ANSI with iCE colours forced on, SAUCE iCE flag set, `.ice` extension. Blinking cells of a non iCE canvas become bright backgrounds (reported).
4. **PCBoard.** `@Xbf` codes (the blink bit in b), CR LF, SAUCE Character/PCBoard with width and lines (iCE flag set only for iCE art, which the SAUCE spec leaves zero). A literal `@` is followed by a repeated colour code so `@X..` or `@CLS@` in the text is never read as a code. `@X00` and `@XFF` save and restore the colour in PCBoard (PPL guide), so black on black is written as `@X07` for blanks and `@X08` for text (reported), as the screen designer does. Cost if wrong: one byte pattern looks slightly different on a real PCBoard.
5. **Wildcat.** `@bf@` codes, CR LF, a colour code at the start (so the reader recognizes the file) and after every literal `@`. No SAUCE: there is no SAUCE type and the registry says Wildcat does not read SAUCE; so iCE and widths over 80 are not recorded (reported). Extension `.bbs` (the registry's suggestion). Cost if wrong: a wide or iCE Wildcat file reads back at 80 columns or blinking.
6. **Avatar/0 and AVT/0+.** ^V^A attribute (and ^V^B for blink), ^Y repeat for 4 or more equal characters, CR LF, SAUCE Character/Avatar. Control code cells become their lookalikes (as the ANSI writer). AVT/0+ is a separate Save As entry: it adds the ^V^Y pattern repeat for repeating patterns of 2 to 8 characters of one colour when that is shorter; AnsiView's file reader learns ^V^Y. Plain AVT/0 stays the default because AVT/0 only readers do not know ^V^Y. Cost if wrong: an extra menu entry.
7. **Embedded fonts.** A file's embedded font (XBin, ADF, IDF) is kept on the canvas; the editor draws with it and ADF, IDF and XBin saves write it (XBin with its height); ANSI style saves keep only the font name (reported as before).
8. **Retro platforms.** Export is a standalone Screen > Export for Retro Platform... (save panel with the platform and the documented name), not a BBS profile setting: no registry package documents a PETSCII, ATASCII or Viewdata folder layout except Synchronet's `.seq` naming and Telstar's frame JSON. Cells are matched by glyph shape (the CP437 glyph sampled to the platform font size) and colour; what cannot be shown (several background colours on a C64 line, colours on an Atari, attribute cells in Viewdata) is counted and reported by playing the result through the platform's terminal and comparing. Art wider or taller than the platform screen is cut (reported). Cost if wrong: an artist must redesign at 40 columns, which the warning says.
9. **Retro appearance.** Original design: DOS blue window chrome (#0000AA family darkened for contrast), light grey and white text, yellow accents, the bundled IBM VGA font for status and hint labels only (not for controls, tables or editable text, so readability and Dynamic Type style sizes stay). The base is dark aqua so every system control stays legible. Contrast of every text and background token pair is computed and must be at least 4.5:1 (tests). Cost if wrong: a user who wanted the whole UI in the VGA font sees only labels in it.
10. **App Store entitlements.** `Packaging/appstore/project-appstore.yml` and its generated `AnsiView.entitlements` gain `com.apple.security.files.bookmarks.app-scope` (used by the transfer folder, capture folder, export profiles, RIP icon folder and library bookmarks), matching the Developer ID variant. Extensions unchanged.
