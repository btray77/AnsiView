# AnsiView 2.0 Plan 3: Viewing and Finder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap items 13 to 19: zoom presets with integer scaling, a full screen presentation mode, a SAUCE info sheet, a folder (and art pack) slideshow, a gallery of thumbnails, Finder thumbnails through a Quick Look thumbnail extension, and Spotlight indexing through a Core Spotlight import extension.

**Architecture:** Pure logic goes in AnsiCore: `Zoom.swift` (canvas size for a zoom mode), `ArtInfo.swift` (the info rows for a file), `ArtCollection.swift` (art file filtering and ordering, slide stepping, a small ZIP reader for art packs), `Thumbnail.swift` (thumbnail crop, size and render), `ArtText.swift` (searchable text and Spotlight fields). `Shared/AnsiPlayer.swift` gains a per window zoom mode and the `onFinished` fix. The app target gains `ArtInfoView.swift`, `Slideshow.swift`, `Gallery.swift` and `Presentation.swift` (AppKit windows, so they can be checked in a harness). Two new sandboxed app extensions, `AnsiThumbnail` (`com.apple.quicklook.thumbnail`) and `AnsiSpotlight` (`com.apple.spotlight.import`), embed in the app and link AnsiCore.

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, AppKit, SwiftUI commands, QuickLookThumbnailing (`QLThumbnailProvider`), CoreSpotlight (`CSImportExtension`, macOS 12+), Compression (raw DEFLATE for ZIP), XcodeGen.

**Spec:** `docs/ROADMAP-2.0.md` (items 13 to 19) plus the coordinator's notes for plan 3.

## Rulings

1. **Zoom modes (item 13).** Per window, not persisted: `fit` (today's behaviour, default), `integerFit` (the largest whole number of device pixels per font pixel that fits; scrollers fit the width), `scale(1|2|3)` (1x is one point per font pixel, as the window's default size). View menu: Fit to Window (Command 0), Integer Fit (Option Command 0), Actual Size (Command 1), Zoom 2x (Command 2), Zoom 3x (Command 3). The menu items are buttons with no checkmark; the HUD names the new zoom. Cost if wrong: a Picker bound to a focused object later.
2. **Integer scaling and the 4:3 aspect.** `scale(n)` keeps the exact legacy stretch (height is n x aspect, rounded per canvas). `integerFit` makes both axes whole device pixels: horizontal k, vertical `round(k x aspect)`, so a legacy aspect file is square at k = 1 or 2 and approaches 4:3 as k grows (k = 5 is exact). The clip view rounds its centering offset to the backing pixel grid so even pixels stay even. Cost if wrong: one function (`Zoom.canvasSize`).
3. **Presentation (item 14).** View > Presentation Mode (Shift Command P). A borderless black window covering the screen of the current window, `NSApp.presentationOptions = [.hideDock, .hideMenuBar]`, cursor hidden (it reappears on mouse move and hides again after 2 s still), art centered and fitted, no scrub bar. It hosts a new player of the same file that takes over the playback position; Escape (or the same command) exits and hands the position back. In a slideshow it presents the slideshow, and the arrows keep moving between files. Rejected: native full screen, because SwiftUI owns the window delegate and the title bar and menus would still slide in.
4. **Info (item 15).** File > Get Info (Command I) shows a sheet on the window with the rows from `ArtInfo.rows`. A file without SAUCE shows the line "No SAUCE record" and still lists format, columns and file size. Return or Escape closes it.
5. **Slideshow (item 16).** Slideshow > Start Slideshow (Option Command S). From a gallery: starts at the selected item. From a document window: lists the file's folder if the sandbox allows (it normally does not), otherwise asks once with an NSOpenPanel opened on that folder; the security scoped URL is started on choice and stopped when the slideshow window closes. Left and Right (and Slideshow > Next Art / Previous Art, Option Command Right / Left) move between files and wrap at the ends; in a slideshow the arrows change files, not frames (Previous Frame and Next Frame stay in the Playback menu). Slideshow > Auto Advance (off by default) and Dwell Time (5, 10, 20 or 30 s, default 10): static art advances after the dwell; animations advance a dwell after `onFinished` (so Hold Final Frame waits for a click, as plan 2 intended). Plan 2's minor is fixed: a seek or scrub that reaches the end of a playback in progress now calls `onFinished`.
6. **Art packs (item 17).** An art pack is a `.zip` file. AnsiCore reads its central directory and inflates stored and DEFLATE entries (Compression's raw DEFLATE); entries with other methods (old PKZIP shrink and implode) are skipped and the gallery says how many. Directories inside the archive are flattened, `__MACOSX` and dot files are ignored.
7. **Gallery (item 17).** File > Open Folder or Art Pack (Shift Command O) opens a gallery window: a grid of 200 point thumbnails with names, rendered on a background queue (concurrency = active processor count) and filled in as they finish. Double click on a folder item opens it as a normal document; on a pack item it opens the slideshow at that item (pack entries have no file URL).
8. **Thumbnails (items 17, 18).** A thumbnail shows the finished art from the top, cropped to at most a square (height at most width, after aspect), fitted into the requested size, never upscaled past 2 points per font pixel; upscaling uses nearest neighbour and downscaling uses high quality interpolation. The Finder extension sets the badge to the uppercased extension.
9. **Spotlight (item 19).** Mechanism: `CSImportExtension` with extension point `com.apple.spotlight.import` (SDK header `CoreSpotlight/CSImportExtension.h`, `API_AVAILABLE(macos(12.0))`, and Xcode 26.6 ships it as the "Spotlight Import Extension" template). Legacy `.mdimporter` bundles are rejected: they cannot ship in a sandboxed App Store style app and Apple's template list no longer offers them. Fields: `title` (SAUCE title, else nil), `authorNames` and `creator` (SAUCE author), `organizations` (SAUCE group), `contentCreationDate` (SAUCE date), `comment` (comment lines joined), `fontNames` (SAUCE font), `kind` (format name), `textContent` (the art's text), `pixelWidth`/`pixelHeight` (1x size).
10. **Searchable text.** The finished screen as Unicode lines with trailing spaces trimmed and trailing empty lines dropped; block, shade and box drawing characters (U+2500 to U+259F) become spaces so words stand out; capped at 100,000 characters.

## Review Focus

- A ZIP with a bad central directory, an entry whose sizes run past the end, or a truncated DEFLATE stream must return an error or skip the entry, never crash (Task 3 tests `corruptZipThrows`, `truncatedEntryIsSkipped`).
- An empty folder, a folder of only non art files, and art files with upper case extensions (`.ANS`) (Task 3 tests `filtersAndSortsLikeFinder`, `emptyListStepsNowhere`).
- An empty or zero length art file must give a thumbnail without crashing and a "No SAUCE record" info (Task 4 test `emptyFileThumbnail`, Task 2 test `noSauceRows`).
- Zoom with a zero or tiny window, and integer fit for art bigger than the window (falls back to 1 device pixel) (Task 1 tests `zeroAvailableKeepsMinimum`, `integerFitNeverBelowOnePixel`).
- Very tall art (thousands of rows) in thumbnails and Spotlight text must stay bounded (Task 4 test `tallArtIsCroppedSquare`, Task 9 test `textIsCapped`).
