# 16colo.rs Previews Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap items 35, 36 and 37 (pulled forward): a preview pane in the 16colo.rs browser that shows a selected file at once (thumbnail, then the real art in AnsiView's own player), a thumbnail grid of a pack's files, a small preview on each pack row, a grid / list toggle in the browser and in local galleries, and a capped disk cache that keeps working offline.

**Architecture:** Pure logic in AnsiCore: `SixteenColors.swift` gains image URLs (`tn`, `x1`), cache key names and the pack's cover file; a new `RequestLane` (in the same file) orders waiting requests by priority so a selection never queues behind thumbnails; a new `DiskCache.swift` holds files under a byte cap with least recently used eviction. App code: `SixteenColorsClient` (in `App/SixteenColorsBrowser.swift`) sends every request through one lane with the existing 1 s spacing and stores everything in the `DiskCache`; a new `App/SixteenColorsPreview.swift` is the preview pane (hosting the shared `AnsiPlayerViewController`); the browser gains a files grid (reusing `GalleryCollectionView` and `GalleryItem`), pack row thumbnails and the layout toggle; `App/Gallery.swift` gains a list layout and the shared toggle.

**Tech Stack:** Swift 6 toolchain, AppKit, Swift Testing (AnsiCore), XcodeGen, URLSession.

**Spec:** `docs/ROADMAP-2.0.md` items 35 to 37, plus the owner's words: "16colo.rs preview when I select it see a preview" and "an icon image of the supported files for the 16colo.rs or something where I can see things without opening them directly". Earlier browser design: `docs/superpowers/plans/2026-10-30-ansiview-2.0-plan-5-distribution.md` decision 6.

## Decisions (rulings, with cost if wrong)

1. **Field names, confirmed live** (2026-10-30, `curl https://api.16colo.rs/v1/pack/0196ciph`, HTTP 200, 14,970 bytes): each file has `file.tn.uri` (`/pack/<p>/tn/<f>.png`, width 160) and `file.x1.uri` (`/pack/<p>/x1/<f>.png`, width 720); the pack has `fileid` (`FILE_ID.DIZ`). Thumbnail headers: `content-type: image/png`, `cache-control: max-age=604800`. A missing thumbnail is HTTP 404 with an HTML body. Cost if wrong: decoding returns nil URLs and the panes show placeholders.
2. **Sequential, 1 s spacing for images too.** 16colo.rs publishes no rate limit or concurrency policy (checked for plan 5); concurrent fetching is therefore not "allowed", so AnsiView keeps one request at a time and shows placeholders. Order is by priority: `.user` (listings, the selected file's art, its `x1`) before `.grid` (visible grid thumbnails) before `.packRow` (visible pack row thumbnails); FIFO within a priority. Cost if wrong: a full grid of 40 files takes about 40 s to fill; switching to 2 at a time later is a one-line change in the lane pump.
3. **Pack row preview = the pack's FILE_ID.DIZ thumbnail**, the image 16colo.rs's own year pages show (checked: `https://16colo.rs/year/1996/` lists `<img src="/pack/<p>/tn/FILE_ID.DIZ.png">` for 19 of 20 packs; the other was `FILE_ID.ANS`). The year listing carries no image field, so for packs whose file list is not known the row asks for `tn/FILE_ID.DIZ.png` (one request); a 404 is remembered for the session and the row shows a placeholder; once the pack's file list is known (it was selected, or is in the disk cache) the row uses `PackDetail.cover` (the `fileid` file, else the first file with a `tn`). Cost if wrong: some rows show a placeholder although the pack has art.
4. **Preview flow:** show the cached `tn` instantly when it is on disk (no request is spent on `tn` for a selection: the art itself is the better use of the next slot); then download the file (cached) and render it in `AnsiPlayerViewController` (animated art plays, blink blinks, tall art scrolls at fit width); for files AnsiView does not open (`isViewable == false`: pictures, programs, archives, music) or that fail to download, show the `x1` PNG in a scroll view. SAUCE title, author and group show under the art.
5. **Disk cache:** `Caches/16colors/` with a 200 MB (209,715,200 bytes) cap over `api/`, `images/` and `files/`; `packs/` (ZIPs that a gallery may still be reading) is not counted or evicted. Least recently used by the file's modification date, which every cache hit sets to now. The newest entry is never evicted. API JSON is written to disk on every success and read from disk only when the network fails as offline. Only data starting with the PNG signature is stored as an image (an HTML error page served as 200 never sticks). Cost if wrong: the cache grows past 200 MB by at most one file.
6. **Layout memory:** `UserDefaults.standard` keys `galleryLayout` and `sixteenColorsLayout`, values `grid` or `list`, default `grid` for both (the owner asked to see art without opening it). Cost if wrong: one default changes.
7. **Open in Editor** goes through a new `onEditFile: ((URL) -> Void)?` callback wired in `AnsiViewApp.swift` (keeps the browser free of editor types). Save to... copies the downloaded file to a save panel location starting in Downloads, with the file's original name.

## Review Focus

1. Arrowing quickly through 10 files: only the last one's art is downloaded; earlier waits are cancelled before the network (Task 4 harness `staleSelectionsNeverFetch`).
2. A thumbnail grid of a large pack must not delay the selected file: a `.user` request waiting behind 20 `.grid` requests goes next (Task 2 `userBeforeQueuedThumbnails`).
3. Offline after a previous session: years, the pack and its thumbnails come from disk, with "Offline" in the status (Task 4 harness `offlineUsesDisk`).
4. Scrolling a 900 pack year: rows that scroll away cancel their pending thumbnail (Task 6 harness counts requests after scrolling).
5. A hostile image path (`/pack/../x1/../../a.png`) never names a cache file outside the cache (Task 1 `imageCacheNameRejectsTraversal`).
