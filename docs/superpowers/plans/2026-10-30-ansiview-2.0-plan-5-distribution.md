# AnsiView 2.0 Plan 5: Distribution, Samples, Integrations and Accessibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap items 28, 29, 30, 31, 33 and 34: a Homebrew formula for `ansirender` (with `--version`), Sparkle updates for the direct download build, original bundled sample art with File > Open Sample, a 16colo.rs browser, Open in Moebius / PabloDraw, and VoiceOver access to the art's text.

**Architecture:** Pure logic goes in AnsiCore: `SixteenColors.swift` (16colo.rs URL building, JSON models, local cache names, a request spacing clock), `ArtText.accessibility...` (VoiceOver value and description), `ArtEditors.swift` (known editors and their bundle identifiers), `UpdateKey.swift` (is a SAUCE-like placeholder or a real EdDSA public key). App code: `App/SixteenColorsBrowser.swift` (window, client, downloads), `App/EditorHandoff.swift`, `App/Updates.swift` (Sparkle, compiled only with `SPARKLE_UPDATES`), `App/Samples.swift` (Open Sample menu). The art view's accessibility lives in `Shared/AnsiPlayer.swift` (so Quick Look gets it too; no new entitlement there). Sample art is generated by `Packaging/samples/generate.swift` into `Samples/`, bundled as a folder resource. The Homebrew formula lives in `Packaging/homebrew/ansirender.rb`; Sparkle tooling in `Packaging/sparkle/`; the Mac App Store variant spec in `Packaging/appstore/project-appstore.yml`.

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, AppKit, SwiftUI commands, URLSession, Sparkle 2.10.1 (Swift Package Manager), Homebrew 7, XcodeGen 2.45.

**Spec:** `docs/ROADMAP-2.0.md` (items 28 to 34 except 32) plus the coordinator's notes for plan 5.

## Global Constraints

- macOS 14.0 or later, universal; `AnsiCore` imports no AppKit or UIKit.
- App and every extension stay sandboxed. This plan adds to the app only: `com.apple.security.network.client` (16colo.rs and Sparkle's appcast and update download) and Sparkle's two `mach-lookup` temporary exceptions (`$(PRODUCT_BUNDLE_IDENTIFIER)-spks`, `-spki`, required by Sparkle's installer XPC service in a sandboxed app). The Quick Look, Thumbnail and Spotlight extensions gain nothing.
- No em-dash characters anywhere in code, UI text, docs or commit messages.
- Bump `CURRENT_PROJECT_VERSION` in `project.yml` with each task commit; `MARKETING_VERSION` stays `2.0.0`.
- `./install.sh` prints `** BUILD SUCCEEDED **` at the end of every task; the Quick Look preview keeps working.
- Release keeps `CODE_SIGN_INJECT_BASE_ENTITLEMENTS: NO`.
- Regression: `ansirender --stats ../extracted/TWSUPP/*.ANS | sed -E 's/ format=.*//'` keeps 15 `animated=Y` and 8 `blink=Y` of 61.
- No third party art in the repo. Samples are generated by a committed script; 16colo.rs fixtures are metadata only (names, years, URLs), trimmed.
- Do not push, tag, publish, create repositories or releases, or run Sparkle's `generate_keys`.

## Rulings

1. **`--version` (item 28).** `ansirender --version` (and `-V`) prints `ansirender 2.0.0 (41)` (marketing version, build number) and exits 0. The tool gets an Info.plist embedded in its binary (`CREATE_INFOPLIST_SECTION_IN_BINARY`), read through `Bundle.main`. Cost if wrong: one setting.
2. **Homebrew (item 28).** `Packaging/homebrew/ansirender.rb` builds from a source tarball of a tagged release (`https://github.com/btray77/AnsiView/archive/refs/tags/v2.0.0.tar.gz`) with `xcodegen` (build dependency) and `xcodebuild`, ad hoc signed, derived data and package checkouts inside the build directory, and `-IDEPackageSupportDisableManifestSandbox=YES` (Swift Package Manager cannot nest its manifest sandbox inside Homebrew's build sandbox: `sandbox_apply: Operation not permitted`); it installs only `bin/ansirender` and the `AnsiCore_AnsiCore.bundle` it loads fonts from, next to the binary in `libexec`, with a `bin` wrapper link. `head` builds `main`. The test block renders a generated ANSI string to PNG and checks `--version`. Building from source (rather than a prebuilt binary) because it needs no notarized asset and Homebrew's audit prefers it; cost if wrong: users need Xcode (not just the Command Line Tools) to install. Local testing uses a throwaway local tap (`brew tap-new`) and a `file://` tarball of `git archive HEAD`, then `brew untap`. Creating the public tap repository (`btray77/homebrew-ansiview`) and the tag are owner steps.
3. **Samples (item 30).** Four original pieces, generated by `Packaging/samples/generate.swift` (run with `swift Packaging/samples/generate.swift Samples`), committed in `Samples/`: `Welcome.ans` (static, 80 x 25, SAUCE title, author, group, date, comments, font `IBM VGA`), `Rocket Launch.ans` (an animation: cursor positioning redraws a rocket and a countdown; `AnsiAnalysis.isAnimated` is true), `Sunset 24-bit.ans` (half block pixels in `38;2` / `48;2` colours, more than 16 distinct colours, SAUCE), `Custom Font.xb` (XBin with its own palette and an embedded 8x16 font drawn by the script). The generator is deterministic (same bytes on every run; a test checks the committed files parse as described). Bundled as a `Samples` folder resource; File > Open Sample lists them by name (extension dropped) and opens them read only from the bundle through `NSDocumentController`. Cost if wrong: regenerate.
4. **VoiceOver (item 34).** Set through the `setAccessibility...` setters when the view loads (and when the file name changes). The art view's role is static text with role description "ANSI art". Its accessibility value is the finished art's text (`ArtText.plainText` of the final screen, not the frame on screen, so it does not change during playback): rows as Unicode, trailing spaces trimmed, trailing empty rows dropped, block, shade and box drawing characters as spaces so VoiceOver reads words, not "full block" per cell. Its label (AXDescription) is `"<title>" by <author>, <group>` from SAUCE, any part omitted when empty, then `, ANSI art` (the format name); without SAUCE it is the file name (when known) and the format, else just the format. An empty text value is the string `No text`. Cost if wrong: two functions.
5. **Editors (item 33).** File > Open in Moebius and File > Open in PabloDraw. Moebius `org.andyherbert.moebius` (electron-builder `appId` in the Moebius repo), PabloDraw `ca.picoe.pablodraw` (`Source/PabloDraw/Info.plist` in the PabloDraw repo). The app is found with `NSWorkspace.urlForApplication(withBundleIdentifier:)` at click time; the file opens with `NSWorkspace.open(_:withApplicationAt:configuration:)`. Not installed: an alert says so with a Download button (the editor's web page). A piece without a file on disk (inside a ZIP pack) or no art window: an alert explains. Items stay enabled so they can explain. Cost if wrong: a table.
6. **16colo.rs API (item 31).** Public, read only, unauthenticated API at `https://api.16colo.rs/v1/` (documented at https://16colo.rs/api/): `year` (pack counts per year), `year/<year>?pagesize=500&page=N` (packs), `pack/<name>` (files). No published terms or rate limit (checked https://16colo.rs/api/ and /faq/; the FAQ allows linking and mirroring and says the art stays its authors' property). AnsiView therefore limits itself: at least 1 second between request starts (counting requests already scheduled), responses cached in memory for the session, downloaded packs and files cached in the container's Caches folder and reused. User-Agent `AnsiView/2.0.0 (build 41; macOS; +https://github.com/btray77/AnsiView)`. Downloads: pack ZIP from the `download` URL the API gives (absolute or relative to `https://16colo.rs`), single files from `https://16colo.rs/pack/<pack>/raw/<file>` (path components percent encoded). Packs open in the gallery (`ArtCollection.open(scoped: false)`), single files as documents; a file whose extension AnsiView does not open (`.CIP`, `.WOH` and other group extensions, which are ANSI) is saved with `.ans` appended; images, executables, archives and music are listed but not openable. Errors: offline (`URLError.notConnectedToInternet`, `.networkConnectionLost`, `.cannotFindHost`, `.timedOut`) shows "You appear to be offline" with a Retry button; HTTP errors show the status; bad JSON shows "16colo.rs sent something AnsiView could not read". Cost if wrong: the browser is one file plus a pure model.
7. **Network entitlement.** `com.apple.security.network.client` (outgoing connections only) is the narrowest entitlement that lets the sandboxed app fetch the API, files and the appcast. No server entitlement. Extensions do not get it. Because the app has it, Sparkle's Downloader XPC service is not enabled (Sparkle's sandboxing guide: only needed without network client).
8. **Sparkle (item 29).** Sparkle 2.10.1 via SPM, `SPUStandardUpdaterController(startingUpdater: false, ...)` started only when `SUPublicEDKey` is a real key (base64 of 32 bytes) and `SUFeedURL` is https. The committed key is the placeholder `REPLACE_WITH_SPARKLE_PUBLIC_ED_KEY`: the updater does not start, a log line says "Updates disabled: SUPublicEDKey is a placeholder", and AnsiView > Check for Updates... shows an alert saying updates are not set up in this build. Info.plist: `SUFeedURL`, `SUPublicEDKey`, `SUEnableInstallerLauncherService = YES`; automatic checks are left to Sparkle's default (it asks the user on the second launch). The Swift package ships Sparkle's helpers (Installer.xpc, Downloader.xpc, Autoupdate, Updater.app) ad hoc signed, so a build phase (`Packaging/sparkle/sign-sparkle.sh`, after Embed Frameworks) re-signs them inside out with the app's identity, hardened runtime and timestamp, as Sparkle's sandboxing guide describes; Xcode then signs the app. Feed: `https://raw.githubusercontent.com/btray77/AnsiView/main/docs/appcast.xml`: served from the public repo with no extra setup (no Pages site to enable), changes on the next push to `main`, and the path also works with GitHub Pages from `/docs` should the owner switch (`https://btray77.github.io/AnsiView/appcast.xml`). The update itself is the notarized DMG attached to a GitHub release. Cost if wrong: one Info.plist key, but shipped builds keep the old URL forever, so it must be right before 2.0 ships.
9. **Appcast script.** `Packaging/sparkle/update-appcast.sh <dmg>` runs Sparkle's `generate_appcast` (from the SPM artifacts, `build/SourcePackages/artifacts/sparkle/Sparkle/bin`) on a staging folder holding the DMG, with `--download-url-prefix https://github.com/btray77/AnsiView/releases/download/v<version>/`, `--link`, `--maximum-deltas 0`, and an optional `--ed-key-file` (for testing with a throwaway key; normally the key comes from the owner's keychain), merging into `docs/appcast.xml`. The script checks the item it produced (version, length, signature present) before replacing the file. Verified here with a throwaway key generated in the scratchpad by CryptoKit (not `generate_keys`, never committed).
10. **Mac App Store variant.** Sparkle code is compiled only under the Swift condition `SPARKLE_UPDATES`, set on the AnsiView target. `Packaging/appstore/project-appstore.yml` includes `project.yml` and replaces the packages (no Sparkle), the AnsiView target's dependencies, compilation conditions, post build scripts and entitlements (no mach-lookup exceptions). The `SU` Info.plist keys stay (inert without Sparkle; replacing `info` would duplicate every document type). `xcodegen generate --spec Packaging/appstore/project-appstore.yml` gives `AnsiViewAppStore.xcodeproj`; it must build. Store submission itself (profiles, App Store signing) is out of scope.

## Review Focus

- A malformed or hostile 16colo.rs response (missing fields, wrong types, a file name with `/` or `..`): decoding fails cleanly or the name is sanitised; nothing is written outside the cache folder (Task 5 tests `rejectsTraversalNames`, `decodesMissingOptionalFields`).
- Offline: the browser shows the offline message and Retry, no crash (Task 6 harness with an unreachable host).
- Sparkle with the placeholder key: the updater never starts and no Sparkle error dialog appears (Task 7, live app log and harness).
- The Quick Look extension: no network entitlement (`codesign -d --entitlements`), preview still registered.
- Accessibility: the value is the art's text through `accessibilityAttributeValue(.value)` and through `AXUIElement` when the process is trusted.
