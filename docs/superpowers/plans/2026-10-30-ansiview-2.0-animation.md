# AnsiView 2.0 Animation Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) with superpowers:test-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Roadmap item 59 and owner brief section 5: a flipbook ANSI animation editor in AnsiView's editor. New Frame copies the previous screen, the user changes it, and export writes only what changed (as drawn, top down, or full redraw), with delays made of harmless padding bytes that cost time at a chosen baud, so the result plays in any viewer that emulates a baud rate.

**Owner's words:** "I also want a animated easy editor, that will do screen by screen, copy last screen and then let you do changes. Either do them as entered or screen refresh top down of changes."

**Architecture:** Pure logic in AnsiCore with Swift Testing tests:
- `Animation.swift`: `AnimationFrame` (layers, active layer, delay, edit log), `CellEdit`, `AnimationOrder`, `PaddingDelay`.
- `AnimationEncoder.swift`: frames to an `.ans` byte stream in one of three orders, with padding delays, optional AnsiView frame markers (custom extension, off by default), and `AnimationStreamCheck` (standard ANSI versus extension).
- `AnimationImporter.swift`: segments an ANSI stream into frames where the screen settles.
- `CanvasEditorFrames.swift` plus small changes to `CanvasEditor.swift`: frames in the editor, undoable frame commands, edit-order recording and record mode timing.
- `Layers.swift`: `ArtProject` version 2 keeps every frame.
- `AnimationHelp.swift`: tooltips, status hints and the (?) explanations.
- `AnsiTerminal.swift`: counts padding pauses so AnsiView's own exports read as animated.

The app adds `App/AnimationTimeline.swift` (timeline strip, controls, preview window, export sheet, import) and small hooks in `App/AnsiEditor.swift` (timeline under the canvas, onion skin drawing) and `App/EditorToolCommands.swift` (Animation menu).

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, AppKit, SwiftUI commands, XcodeGen.

**Spec:** `docs/ROADMAP-2.0.md` item 59, `docs/STUDIO-CHECKLIST.md` section 5, the owner design accepted in the coordinator brief (quoted in Rulings).

## Rulings

1. **Frames.** A frame is its own layer stack (ruling 11 of the editor tools plan: `frames: [{layers}]`), an active layer, a delay in seconds (default 0.5, clamped 0 to 60) and an edit log. New Frame inserts a copy of the current frame after it with an empty edit log and edits it; Duplicate Frame copies including the log; Delete removes the current frame (never the last); frames reorder by drag. Frame commands are undo steps; choosing a frame is not (like choosing a layer). Size, iCE and SAUCE changes apply to every layer of every frame. Cost if wrong: one model.
2. **Edit order.** While the timeline is open the editor compares the flattened frame after every change with the one before and appends each changed cell to the frame's log (a cell already last in the log is not added twice). The log is part of the undo state, so undo removes its entries. Export "as drawn" orders the changed cells by their last entry in the log; changed cells not in the log (for example from showing a layer) follow in top down order. Cost if wrong: as drawn falls back to top down for those cells.
3. **Record mode.** Record (off by default) stamps each log entry with seconds since recording began. An as drawn export with "Replay recorded pauses" on inserts padding for each gap between consecutive entries of at least 0.05 s, capped at 2 s per gap. Cost if wrong: drawing replays at line speed.
4. **Export orders.** The stream starts `ESC[0m ESC[2J ESC[H` (a known blank screen). Each frame is written as the cells that differ from what the screen shows: as drawn (ruling 2), top down (row by row, left to right), or full redraw (`ESC[0m ESC[2J`, then every non-blank cell top down). Each frame begins with an absolute cursor position (CUP), so its bytes do not depend on padding before it. Within a frame the shortest of CUP, CUF, CUB, CUU, CUD is used, and a gap of up to 3 unchanged cells is rewritten instead when that is shorter and needs no colour change. After a write in the last column the cursor counts as unknown (ANSI.SYS wraps at once, VT100 terminals wait), so the next move is CUP. Colours use the ANSI writer's `SGRState`. Codes that terminals act on (0x00, 0x07, 0x08, 0x09, 0x0A, 0x0D, 0x1A, 0x1B) are written as the plain text export's lookalikes, and UTF-8 only cells as their CP437 code; the proof compares against these written forms. SAUCE follows the stream (iCE flag, size, title, author, group). The stream ends `ESC[0m`. Cost if wrong: bigger files.
5. **Delay padding.** At baud B one character takes 10 / B seconds (8 data bits, start and stop bit, as the player assumes). A delay of d seconds is `round(d * B / 10)` character times. The padding byte is CR (0x0D). Why it is invisible: CR moves the cursor to column 1 of the current line and draws nothing; once there, more CRs change nothing. ANSI.SYS, VT100 family terminals, SyncTERM, NetRunner and AnsiView all treat it this way, and it is a byte a 1980s terminal is built for. The hold of frame k is measured from the byte that completes it to the first byte after which the screen differs; that includes the next frame's lead in (its CUP and SGR before the first visible change), so the padding is `max(0, round(d * B / 10) - leadIn)`. A hold shorter than the lead in cannot be made; the encoder reports the achieved hold per frame. Caveats, documented in help: a terminal set to add a line feed after each CR (rare, off by default everywhere) would move down; a viewer that shows files instantly (no baud emulation) shows no delays at all; baud 0 (unlimited) writes no padding. The cursor rests at column 1 during a delay. Cost if wrong: a different padding byte.
6. **Custom extension (off by default).** "AnsiView frame markers" add `ESC[?2416;<frame>;<delay ms>z` after each frame, so AnsiView re-imports exact frames and delays. It is a private CSI that AnsiView's player ignores (tested); other terminals should ignore a private sequence they do not know, but that is not verified for every terminal, so it is off by default, labelled "AnsiView extension" in the export sheet, and `AnimationStreamCheck` reports any stream containing it as "uses an AnsiView extension". The marker bytes count toward the padding budget, so timing stays the same. Cost if wrong: one option.
7. **Import.** `AnimationImporter` plays the stream one step at a time (a character or a whole escape sequence) and splits a frame when the screen settles, which means one of: (a) an AnsiView frame marker; (b) a clear screen (`ESC[2J`) after drawing; (c) an idle run: at least `idleBytes` (default 48, which is 0.2 s at 2400 baud) consecutive bytes that change nothing visible; (d) an overwrite: a step visibly changes a cell that already changed since the frame began. "Visibly" means two cells that are both blank glyphs (space, NUL, 255) on the same background count as the same (a recoloured space is not a redraw). Measured on the corpus before settling: 24 bytes split TWHELLO's main picture into partial frames (runs such as `ESC[40m CR LF ESC[44m ESC[2;7H ESC[30;40m` are 24 bytes), and exact cell comparison split SHPBLUP's first picture early; 48 bytes and visible comparison fixed both (contact sheets looked at). The frame is the screen just before the splitting step. Delays: a marker's value, an idle run's length at the import baud (default 2400), else 0 (the drawing itself is the timing). Each frame's edit log is the stream's order of changes, so an as drawn export replays the original order. Frames are `AnsiAnalysis.canvasRows` high (25 for animations). Cost if wrong: more or fewer frames; the last frame is always the file's final screen.
8. **Analysis.** `AnsiTerminal` counts pauses: a run of 8 or more CR bytes after something was drawn. `AnsiAnalysis.isAnimated` is also true when the stream has a pause (the 61 file corpus keeps 15 animated). Cost if wrong: an exported animation with no clears, few overwrites and no delays reads as a still in the player.
9. **Project version 2.** `.ansiproj` adds per frame `delay` and `edits` (`[[x, y]]`, or `[[x, y, milliseconds]]` when recorded), and top level `currentFrame`. A project with one frame and no edit log is written as version 1, byte identical to before; otherwise version 2. Readers accept versions 1 and 2. Cost if wrong: a format change before 2.0 ships.
10. **Interface.** Tools > Animation Timeline shows a strip under the canvas: New Frame, Duplicate, Delete, previous / next, delay field, Onion Skin, Record, Play (preview), baud popup (300, 1200, 2400, 4800, 9600, 14400, 19200, 28800, 57600, 115200), Export..., Import..., and (?) buttons for onion skin, export orders and baud padding. Thumbnails (each frame flattened, with its number and delay) are clicked to edit and dragged to reorder; right click offers duplicate and delete. Onion skin draws the previous frame at 35% opacity over the current one (identical cells look unchanged; changed cells show a ghost). Play opens a preview window that plays the exported stream through `AnsiTerminal` at the chosen baud, with the order and elapsed time. Export (sheet): order, baud, replay pauses, frame markers (AnsiView extension), and the format: ANSI `.ans`, GIF or MP4 (through `AnsiExporter.export` at that baud); the sheet shows the byte size of each order for the current frames. Tools > Import Animation... opens an animated `.ans` as frames in a new editor. Every control has a tooltip and a status bar hint (the existing `HintTracker`). Cost if wrong: layout only.

## Review Focus

- A frame taller or shorter than another (layers resized on one frame only): export uses the tallest; every frame compares padded with blank cells.
- Undo after New Frame, Delete Frame and reorder restores frames and the current frame; drawing then undo leaves the edit log as before.
- A delay shorter than the next frame's lead in: the achieved hold is reported, never negative padding.
- Cells in the last column and the bottom right cell: the next move is absolute.
- Import of a stream with no splits (a still): one frame equal to the final screen.
