# AnsiView 2.0 Plan 7: Online (Telnet BBS Terminal) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap item 32: a telnet (and raw TCP) BBS terminal in the macOS app that draws with the AnsiView renderer and fonts, with an address book, correct telnet option negotiation, interactive terminal semantics, BBS keyboard mapping, optional baud emulation, session capture and clear connection errors.

**Architecture:** Everything that can be pure lives in AnsiCore with byte level tests: `Telnet.swift` (the telnet protocol state machine, no I/O), `TerminalEmulator.swift` (a fixed size interactive screen with scroll region, scrollback, device status replies and a streaming parser that survives sequences split across packets), `TextAttributes.swift` (SGR state shared with the file player's `AnsiTerminal`), `TerminalInput.swift` (keys and text to bytes), `BBSAddressBook.swift` (entries, address parsing, persistence format) and `BBSClient.swift` (Network.framework `NWConnection` client that combines the telnet session, baud pacing, capture and error mapping). The app adds `App/BBSTerminal.swift` (terminal window, view, keyboard, menus) and `App/BBSConnect.swift` (connect window with the address book). Nothing is added to `Shared/` (the Quick Look extension compiles it) and no extension gains anything.

**Tech Stack:** Swift 5 mode on the Swift 6.3 toolchain, Swift Testing, Network.framework, AppKit, SwiftUI (connect window form), XcodeGen.

**Spec:** `docs/ROADMAP-2.0.md` item 32 plus the coordinator's scope notes for plan 7 (copied into the rulings below).

## Rulings

1. **Telnet options (RFC 854, 855, 856, 857, 858, 1091, 1073, 1143 style loop prevention).** Accepted from the server's side (server `WILL x`, we answer `DO x`): BINARY (0), ECHO (1), SUPPRESS-GO-AHEAD (3). Accepted on our side (server `DO x`, we answer `WILL x`): BINARY (0), SUPPRESS-GO-AHEAD (3), TERMINAL-TYPE (24), NAWS (31). Everything else is refused (`DONT x` to `WILL x`, `WONT x` to `DO x`); we never `WILL ECHO`. Per option and side the session keeps an enabled flag and a "we asked" flag: a request that matches the current state gets no reply (no loops); a reply to our own request gets no reply; `WONT`/`DONT` of an enabled option is acknowledged once with `DONT`/`WONT`; of a disabled one, not at all. On connect the client sends `IAC DO SGA`, `IAC WILL TTYPE`, `IAC WILL NAWS` (marked as asked). Cost if wrong: a BBS that waits for a different opening, which still negotiates when it asks.
2. **TERMINAL-TYPE.** `IAC SB 24 1 IAC SE` (SEND) is answered `IAC SB 24 0 <name> IAC SE` (IS) cycling `ANSI`, `ANSI-BBS`, `VT100`; after the last, the last name repeats (RFC 1091 end of list). The cycle restarts if TTYPE is disabled and enabled again.
3. **NAWS.** When NAWS becomes enabled (server `DO NAWS`, or its answer to our `WILL`), and on every `resize`, the client sends `IAC SB 31 w_hi w_lo h_hi h_lo IAC SE`; a 255 byte inside is doubled. Sizes are the emulator's columns and rows.
4. **Data path.** `IAC IAC` is a data 255; other commands (NOP, GA, AYT, DM and so on) are dropped; subnegotiations of refused options are dropped; the parser state survives splits at any byte. Received `CR NUL` becomes `CR` while the server is not in BINARY (RFC 854). Outgoing: 255 is doubled; `CR` not followed by `LF` becomes `CR NUL` while our side is not in BINARY. Raw TCP mode passes bytes unchanged both ways and sends no negotiation.
5. **Interactive emulator.** A fixed grid (columns 1...255, rows 1...255, default 80 x 25) with: printable bytes in CP437 (or UTF-8, decoded incrementally across feeds; scalars with a CP437 equivalent use the code, others set `scalar` like `AnsiTerminal`), pending wrap at the last column (autowrap, `ESC[?7l` turns it off), CR, LF and `ESC D` (index, scrolls the region at its bottom), `ESC M` (reverse index), `ESC E` (next line), BS, TAB (8 column stops), BEL (counted for the UI), FF (clears the screen and homes, as BBS terminals do). CSI: `A B C D E F G H f d` (moves, clamped to the screen; `A`/`B` stop at the region edges when inside it), `J` 0/1/2 and `K` 0/1/2 (erase with the current background), `L M` (insert, delete lines in the region), `@ P X` (insert, delete, erase characters), `S T` (scroll up, down), `r` (DECSTBM scroll region, homes the cursor), `s u` and `ESC 7`/`ESC 8` (save, restore cursor; ESC 7 also saves attributes), `m` (shared SGR, ruling 6), `n` (`5n` replies `ESC[0n`, `6n` replies `ESC[<row>;<col>R`, one based), `c` (primary DA, replies `ESC[?1;0c`), `?25h`/`?25l` (cursor visible). `ESC c` resets. Unknown sequences are consumed and ignored; parameters clamp at 9999. Lines that scroll off the top of a region starting at row 0 go to the scrollback (cap 2,000 lines, oldest dropped). Blink uses the blink attribute (not iCE), so blinking text blinks, as on a DOS BBS. Cost if wrong: one sequence draws wrongly.
6. **Shared SGR.** The colour and attribute logic in `AnsiTerminal` moves unchanged into `TextAttributes` (an internal struct with `apply(_ codes: [Int])` and `colors(iceColors: Bool)`), used by both terminals. The 61 file regression must not change.
7. **Keys (ANSI BBS / VT220 style).** Return sends `CR` (the telnet layer adds NUL, ruling 4). Backspace sends `BS` (0x08), or `DEL` (0x7F) when the entry says so. Tab `HT`, Escape `ESC`. Arrows `ESC[A` up, `ESC[B` down, `ESC[C` right, `ESC[D` left. Home (SyncTERM sends `ESC[K` for End, which is erase line everywhere else, so VT220 codes are used): Home `ESC[1~`, Insert `ESC[2~`, forward Delete `ESC[3~`, End `ESC[4~`, Page Up `ESC[5~`, Page Down `ESC[6~` (VT220, understood by Synchronet, Mystic and most door kits). F1 to F4 `ESC O P` to `ESC O S`; F5 `ESC[15~`, F6 `17~`, F7 `18~`, F8 `19~`, F9 `20~`, F10 `21~`, F11 `23~`, F12 `24~`. Control-letter sends the control code (Control-A 0x01 ... Control-Z 0x1A). Text (typed or pasted) is encoded in the entry's encoding: CP437 through `CP437.code(for:)` with unmappable characters dropped, or UTF-8; a pasted `LF` or `CRLF` becomes `CR`. Option combinations type the character macOS produces (so Option-Shift-... gives accented letters that map to CP437). Cost if wrong: one key on one BBS; a table.
8. **Address book.** `BBSEntry: Codable, Equatable, Identifiable` with `id: UUID`, `name`, `host`, `port` (default 23, 1...65535), `username` (optional; Terminal > Send Username types it and Return; passwords are never stored), `fontName` (default `IBM VGA`, any `BitmapFont.supportedNames`), `columns` 80, `rows` 25, `encoding` (`cp437` default, `utf8`), `mode` (`telnet` default, `raw`), `baud` (0 unlimited default, or a `PlaybackSpeed.choices` value), `backspaceSendsDelete` false. Stored as JSON in the app's standard user defaults under `bbsAddressBook` (app only, not the shared suite). Decoding ignores bad data (empty book). `BBSAddress.parse("host")`, `"host:2323"`, `"telnet://host:2323/"`, `"[::1]:23"` give host and port; empty or bad ports return nil.
9. **Connection errors.** `BBSClient` reports `BBSConnectionError` with user facing text: `.hostNotFound(host)` "The BBS address \"host\" could not be found. Check the spelling, or your internet connection." (NWError `.dns`, including a connection that goes to `.waiting` with a DNS error); `.refused(host, port)` "host refused the connection on port N. The BBS may be down, or it may use a different port." (POSIX `ECONNREFUSED`); `.timedOut(host)` "No answer from host after 15 seconds." (our 15 s connect timer, or POSIX `ETIMEDOUT`); `.closedByRemote` "The BBS closed the connection." (receive completes, or `ECONNRESET`/`EPIPE` after connecting); `.other(description)`. A `.waiting` state with a non DNS error also fails at once (a terminal should not silently retry). Disconnect by the user is not an error.
10. **Baud emulation.** `LinePacer` releases received bytes at baud / 10 bytes per second (8N1, the playback rule) using a 60 Hz tick; 0 is unlimited (all at once). Bytes to send are never delayed. The Terminal > Speed menu offers `PlaybackSpeed.choices` (300 to 115200 and Unlimited), per window, defaulting to the entry's value.
11. **Modem sound.** When Playback > Modem Sounds is on, the handshake plays once while connecting (the existing `ModemSoundPlayer`, state `.connecting`) and stops when the session ends; there is no line noise loop during an interactive session (it would play under every keystroke). Cost if wrong: owner wants noise; one line.
12. **Capture and copy.** Terminal > Capture Session... asks for a `.ans` file (save panel, the existing user-selected read-write entitlement) and appends every received data byte after telnet decoding, as received (so it replays in AnsiView at modem speed); Stop Capture closes it. No SAUCE is added (the capture is the raw stream; adding a record later would need the final size). Edit > Copy copies the visible screen as UTF-8 text (`TextConvert.utf8Text`, trailing blanks trimmed).
13. **Rendering.** The view keeps one rendered image per visible row (rendered at scale 1 with `AnsiRenderer` and the entry's font), re-renders a row only when its cells differ from the cached row, and redraws at most 60 times a second from a display timer that checks the emulator's change counter. Blink and cursor blink share a 0.5 s timer. The art is scaled to fit the window keeping its aspect, nearest neighbour. Scroll wheel and Shift-Page Up/Down move through the scrollback; any typed key returns to the live screen. Cost if wrong: frame rate on big floods; measured in Task 5.
14. **Terminal size.** Terminal > Size offers 80 x 25, 80 x 43, 80 x 50, 132 x 25, 132 x 50 (plus the entry's size); changing it resizes the emulator (content kept top left, cursor clamped) and sends NAWS.
15. **Local echo.** None. BBSes echo; if the server refuses ECHO the terminal still sends keys without echoing them locally (the common BBS terminal behaviour). Cost if wrong: typing invisible on a non echoing line mode server.

## Review Focus

- A telnet command, a subnegotiation or a CSI sequence split across two packets at every possible byte: the result equals the unsplit feed (tests `splitAtEveryByteMatches` in Task 1 and `byteByByteFeedMatchesWholeFeed` in Task 2).
- A malicious or broken server: an endless subnegotiation, a huge CSI parameter, cursor moves far outside the screen, a scroll region with top below bottom: bounded memory, no crash, cursor clamped (tests `subnegotiationIsBounded` in Task 1, `hostileSequencesStayInBounds` in Task 2).
- A server that negotiates in a loop (`WILL ECHO` repeated, `DO` then `DONT` then `DO`): replies only on state changes (test `noReplyLoops` in Task 1).
- UTF-8 text split mid character, and invalid UTF-8 bytes in UTF-8 mode: decoded once, invalid bytes shown as CP437 (test `utf8SplitAcrossFeeds` in Task 2).
- Unreachable host, refused port, server closing at once: a clear message, no hang (tests `refusedConnectionIsReported`, `remoteCloseIsReported`, `unknownHostIsReported` in Task 4).
