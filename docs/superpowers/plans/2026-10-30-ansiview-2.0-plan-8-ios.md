# Plan 8: iPhone and iPad App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) with superpowers:test-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver roadmap item 27: a universal iPhone and iPad viewer app for ANSI art that reuses AnsiCore, with a Quick Look preview extension and a thumbnail extension for the Files app.

**Architecture:** AnsiCore already compiles for iOS (audit in Task 1). The playback logic that lives inside the AppKit `AnsiPlayerViewController` is re-expressed as a pure, clock driven `ArtPlayback` value type in AnsiCore (no music, no modem sound), and share exports (PNG and GIF data) as `ArtShareExport`, both with Swift Testing. The iOS code is thin UIKit and SwiftUI in a new `iOS/` folder: a shared `ArtPlayerViewController` (UIScrollView, nearest neighbour image view, pinch zoom, tap to skip or replay, blink) used by the app and the Quick Look extension; a SwiftUI app shell (samples, files in the app's Documents, Open from Files, Open In); and a thumbnail extension that compiles the existing platform neutral `Thumbnail/ThumbnailProvider.swift`. macOS targets and `Shared/AnsiPlayer.swift` are not changed.

**Tech Stack:** Swift 6 toolchain (Swift 5 language mode), SwiftUI, UIKit, QuickLook, QuickLookThumbnailing, Swift Testing, XcodeGen, iOS 17 deployment target, iOS 26.5 simulator.

**Spec:** `docs/ROADMAP-2.0.md` item 27, plus the coordinator's brief (repeated in Global Constraints).

## Global Constraints

- iOS/iPadOS 17.0 or later, universal (TARGETED_DEVICE_FAMILY 1,2). macOS 14 targets unchanged.
- Bundle ids under `com.traynham.AnsiView`: app `com.traynham.AnsiView.iOS`, extensions `com.traynham.AnsiView.iOS.Preview` and `com.traynham.AnsiView.iOS.Thumbnail`. Team 47HEHK53W5, automatic signing for the iOS targets only.
- Extensions get no entitlements at all (no network, no app group).
- Out of scope for this plan: BBS terminal, editor, file transfers, SSH, ANSI music and modem sounds on iOS, 16colo.rs browsing.
- Do not change `CURRENT_PROJECT_VERSION`; do not run `./install.sh`; no keystrokes or osascript; simulator screenshots and offscreen harnesses only. Delete created simulators at the end. `lsregister -u` any macOS app built in the worktree.
- Do not touch `Terminal*`, RIP, `BitmapFont` EGA or `App/Terminal*` files.
- No em-dash character anywhere. Checked with `grep -a` on the diff.
- Regression gate: macOS app builds; `ansirender --stats ../extracted/TWSUPP/*.ANS` keeps 61 files, 15 animated=Y, 8 blink=Y; all AnsiCore tests pass.

## Rulings (with cost if wrong)

1. **Bundle ids** `com.traynham.AnsiView.iOS` (+ `.Preview`, `.Thumbnail`). Universal purchase with the Mac app would want the Mac id `com.traynham.AnsiView`. Cost if wrong: rename three ids before the first App Store submission (free now, impossible after release).
2. **No app group.** The macOS app shares speed settings with Quick Look through an app group; on iOS that needs an App ID group registered on the owner's account. The iOS preview plays at the default 2400 baud. Cost if wrong: Quick Look ignores the speed chosen in the app.
3. **No document browser root.** The app's root is its own list (Samples, On This iPhone/iPad from the app's Documents folder, Open from Files via `fileImporter`) rather than `DocumentGroup`, because a viewer needs no save path and the list can be screenshotted without taps. Files in Documents show in the Files app (`UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`). Files opened elsewhere are read with security scoped access for the read only. Cost if wrong: no Recents list (deferred minor).
4. **Playback engine re-expressed, macOS untouched.** `ArtPlayback` reproduces the macOS player's rules (8N1: baud / 10 bytes per second, 25 row terminal window for tall art following the cursor, finished screen shown when done, instant at baud 0) without music. The macOS player keeps its own copy. Cost if wrong: two copies to keep in step (deferred minor: move macOS onto it).
5. **GIF export** uses AnsiView's own indexed encoder at scale 1 (2 for art 25 rows or less) with frames sampled 10 times a second plus a 3 s hold (blink alternates during the hold). Cost if wrong: share GIFs are coarser in time than macOS exports (15 fps).
6. **Debug only launch hooks** for verification without taps: `-open <name>` opens a sample or Documents file, `-quicklook <name>` presents a `QLPreviewController` for it (which loads the preview extension). Compiled only under `#if DEBUG`. Cost if wrong: none in Release.
7. **Quick Look content types** mirror macOS: preview for `com.traynham.ansiview.ans` and `.asc`; thumbnail for `.ans` only (macOS refuses `.asc` thumbnails; not re-tested on iOS).

## Review Focus

1. Huge or very tall art (1500 rows) on a phone: pinch zoom must stay bounded and memory sane; Fit shows the full width and scrolls.
2. A file opened from Files outside the sandbox: read inside start/stopAccessingSecurityScopedResource, no lingering access.
3. A static file at Instant speed and a 0 byte file: no timer runs, no crash (ArtPlayback test with empty data).
4. Rotation and iPad split view: the art refits on size change.
5. GIF export of a long animation: bounded size (measured on the largest TWSUPP animation).

## Review outcome

A fresh opus reviewer found no Critical issues and six Important ones. Fixed: reopening a changed
outside file kept the old bytes; parsing on the main thread (app and preview); unbounded share GIF
(now at most 600 drawing frames, streamed in two passes); the display link retained the player
and timers had no teardown; backgrounding mid playback jumped to the end. Not done: the version
bump (the coordinator's brief forbids changing `CURRENT_PROJECT_VERSION`; MARKETING_VERSION stays
2.0.0 per the roadmap). Also fixed from the Minors: preview size cap, one share at a time, the
Documents path check, and three missing ArtPlayback tests (one found a real off by one byte).

Deferred minors:
- Open from Files reads the picked file on the main thread (an iCloud file not yet downloaded
  waits there); files copied into Documents/Inbox by Open In are not listed.
- The thumbnail extension has no 16 MB cap (shared Mac source, unchanged).
- `ArtFile` and `AnsiScreen` are not marked `Sendable` (fine in Swift 5 mode, an error under Swift 6).
- iOS targets set `ONLY_ACTIVE_ARCH: YES` in all configurations; no `ITSAppUsesNonExemptEncryption`.
- The player builds `displayedScreen` several times per redraw.
- The Mac player could adopt `ArtPlayback` so there is one copy of the playback rules.
- AnsiCore's networking code is linked into the iOS app and extensions (unused; iOS has no network
  entitlement to withhold). Measured with `otool -L`: Network.framework is linked, as it is in the
  Mac Quick Look extension.
